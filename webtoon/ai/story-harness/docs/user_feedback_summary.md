# 사용자 피드백 정리 — 그림 / 스토리 / 콘티

2026-08 실사용자 테스트(사용자 A 외) 피드백만 추린 문서. 채널/타겟 전략 논의는 별도 문서 참고, 여기는 **"뭐가 문제였고 어디를 고치면 되는가"**만 다룬다.

파일 위치는 grep으로 빠르게 확인한 것 — 실제 수정 전 해당 함수를 열어서 재확인할 것.

우선순위 기준(원 분석 문서 기준 유지):
- **P0** — 과금 전환의 전제조건 (이거 안 고치면 무료여도 못 씀)
- **P1** — 체감 품질 (있으면 확실히 나아짐)
- **P2** — 완성도 (있으면 좋음, 출시를 막지 않음)

## 1. 그림 · 캐릭터 피드백

| 피드백 (사용자 발언/관찰) | 원인 추정 | 고칠 위치 | 우선순위 |
|---|---|---|---|
| "아예 다른 사람이 됐다" — 원본 대비 의상·장신구·헤어·그림체가 전부 다름. 망토를 인식 못함, 묶은머리→푼머리 | 컷이 아니라 **캐릭터 시트 생성 단계**에서 이미 원본과 어긋남 → 이후 전 컷이 오염 | `webtoon-harness/charsheet.py` (시트 생성 프롬프트가 원본 레퍼런스 디테일을 얼마나 강제하는지 확인) + `stylelock.py` (그림체 일관성 체크가 시트↔원본은 안 보고 컷↔시트만 보고 있을 가능성) | **P0** |
| 사용자 제안: 캐릭터 시트를 먼저 보여주고 확인받은 뒤 진행 | 시트 확정 전 사용자 확인 단계가 없음 | `webtoon-harness/charsheet.py` — grep 결과 승인/확인 관련 로직 없음. 시트 생성 직후 파이프라인을 멈추고 승인받는 단계 신설 필요 | **P0** |
| 1컷·2컷 지팡이 디자인이 다름 (소품 불일치) | 소품이 캐릭터 시트에 고정 자산으로 안 박혀있고, 컷마다 새로 그려짐 | `charsheet.py`에 무기/소품을 시트 항목으로 명시 + `scenegen.py`에서 소품을 레퍼런스 이미지로 고정 | **P0** (일관성 이슈라 시트 문제와 동급) |
| 모자를 썼다 벗었다 함 — "이후 모든 컷에서 나타나는 공통 문제" | 위와 동일한 원인(소품/의상 고정 미흡) | 동일 (`charsheet.py` + `scenegen.py`) | **P0** |
| 같은 프롬프트, 같은 모델인데도 그림체가 다르게 나옴 | 컷마다 재현성(시드/레퍼런스 강도)이 낮음 | `webtoon-harness/scenegen.py` — 시드 고정 여부, 레퍼런스 이미지 가중치 확인 | **P1** |
| 나이 비율에 비해 얼굴이 성숙해 보임 (18세 캐릭터인데 나이대 미반영) | 시트 프롬프트에 연령대 지시가 약함 | `charsheet.py` 프롬프트 — 나이 필드를 외모 묘사에 명시적으로 반영하는지 확인 | **P1** |
| SD 넣은 캐릭터가 웹툰에서는 LD로 출력됨. SD/MD/LD 용어 자체가 팀·사용자 간 불일치(SD=머리비중 커야 함, MD=중간등신, LD=실제등신인데 팀은 MD/LD를 SD로 분류한 경우 많았음) | ⚠️ 코드베이스 내 "SD" 라는 이름이 **이미 다른 뜻으로 쓰이고 있음** — `scenegen.py`에서 SD는 "코미디용 2~3등신 chibi 컷"을 가리키는 용어(예: "Korean webtoon chibi / super-deformed (SD) comedy insert"). 사용자 입력 단계의 "SD 등신 비율 캐릭터"와 이름이 충돌 → 혼선의 근원일 가능성 있음 | 용어 정리 먼저: 입력단 등신 비율은 SD/MD/LD가 아닌 다른 이름으로 분리 검토. 실제 등신 반영 로직은 `charsheet.py`(입력 이미지 등신 판별) + `config.yaml`(그림체 프리셋) | **P1** |
| 스티커가 3D 느낌이라 그림체와 안 맞음 → 완전 평면 스타일 필요 | 스티커 생성 프롬프트/모델이 나머지 컷과 다른 스타일 지시를 받음 | `webtoon-harness/strip.py` (스티커 생성부 — 주석에 "여기서만은 이미지 모델이 낫다"고 되어 있어 스티커가 별도 경로로 생성됨을 확인) | **P2** |
| 편지지 글자가 온전히 읽히지 않음 | 이미지 생성 모델이 텍스트 렌더링에 약함 | `scenegen.py` — 텍스트 포함 컷은 이미지 생성 후 텍스트를 별도 오버레이하는 방식 검토 (`bubbles.py`의 말풍선 텍스트 처리 방식 참고) | **P1** |
| 편지지 속 캐릭터 이름이 사용자가 입력한 이름(초롱)과 다르게 출력됨 | 이름 바인딩이 프롬프트에 끝까지 전달 안 됨 | `story-harness/storyload.py` / `story.py` — 캐릭터 이름 변수가 편지/텍스트 소품 생성 프롬프트까지 전달되는지 확인 | **P0** (이름 오류는 자캐러에게 치명적) |
| 3컷 조명이 빨개서 무섭다 — 공포 연출을 요청한 적 없는데 공포 톤으로 감 | 배경/조명 프롬프트가 장면 텍스트(덫, 숲 등)에서 자동으로 어두운 톤을 유추 | `scenegen.py` 조명/무드 프롬프트 — 장르(로판 등)와 무관하게 소재만으로 톤이 결정되는 로직 점검 | **P1** |
| (긍정) 조명 효과 자체는 예쁘다, 신비로운 느낌 좋음 | — | 톤 컬러만 장면 성격에 맞게 조정하면 되는 수준 — 전면 재작업 불필요 | 참고용 |
| 1컷·2컷 배경이 완전히 동일 — "대충 만든 느낌" | 배경 자산이 "존(zone)" 단위로 재사용되는데, 같은 존 안에서는 컷 간 변주가 없음 | `scenegen.py` — 주석상 "이 Scene 한 장에 붙일 존 배경 자산" 로직 확인. 같은 존이어도 앵글/거리감 변주를 주는 방향으로 보완 | **P2** |
| 포즈 어색함 (예: "이 검 엄청 가벼워요" 컷) | 액션 포즈 프롬프트 디테일 부족 | `scenegen.py` 포즈 지시문 | **P2** |
| 생쥐 디테일 아티팩트 (머리가 발 모양, 새싹이 몸 위에 자람 등) | 이미지 모델의 전형적 생성 오류 | `review.py` — 사후 검수 단계에서 소품/생물 디테일 이상을 걸러내는 체크 추가 검토 | **P2** |

## 2. 스토리 피드백

| 피드백 | 원인 추정 | 고칠 위치 | 우선순위 |
|---|---|---|---|
| 로맨스 판타지를 골랐는데 로맨스가 없음. 로판 필수 요소(황태자·북부대공·마탑주·빙의 등)가 전혀 없음 | 장르가 프롬프트 장식으로만 쓰이고 서사 구조를 규정하지 못함 | `story-harness/story.py` — `resolve_genre_templates`, `genre_promise`/`genre_betrayal` 로직은 이미 존재(코드 확인함). **인프라는 있는데 로판 템플릿 자체에 필수 트로프가 덜 들어있는 것으로 보임** → `prompts/` 안의 로판 템플릿 보강이 핵심 | **P0** |
| 성격에 "장난스럽다"만 적었는데 후반부 급격히 진지해짐 (설정 붕괴) | 사용자가 명시하지 않은 성격 이탈을 막는 검증 게이트가 없음 | `story-harness/story.py`의 `personality` 필드(이미 값은 있음, `p1.personality`) 를 스토리 생성 단계 검증에 실제로 사용 중인지 확인. **`story-harness/test_gates.py`가 이미 존재** — 여기에 "성격 이탈 감지" 게이트 추가가 자연스러운 지점 | **P0** |
| 장난→진지 전환에 빌드업이 없음, "모든 선택을 바꿔놓았다" 류 문장이 뜬금없이 삽입 | 톤 전환에 대한 중간 단계 지시가 프롬프트에 없음 | `prompts/` 스토리 생성 템플릿 — 톤 전환 시 최소 1비트 빌드업을 요구하는 규칙 추가 | **P1** |
| 대사가 "전형적인 AI 문체" (예: "여기서 이렇게 다 보는 앞에서 장난쳐도 되는 걸까, 재밌을지도") | 대사 생성 프롬프트가 일반적/설명적 톤에 치우침 | `prompts/` 대사 생성 템플릿, `bubbles.py`(말풍선 텍스트 삽입 시점) | **P1** |
| "지금, 방금, 들렸어.." 같은 부자연스러운 대사. "저 소리는 누구지?"→"저 소리는 뭐지?"가 자연스러움. "자연의 미세한 소리가 초롱을 부른다" 단어 선택 어색 | 대사 생성 시 구어체 자연스러움 검증 부재 | `prompts/` 대사 템플릿 — 구어체 체크(문어체 잔재 제거) 규칙 추가 | **P1** |
| 마법학교인데 왜 마법을 쓰면 안 되는지 개연성 없음. "다양한 존재들이 모이는 학교"라 해놓고 규칙은 인간 기준만 적용 | 설정 요소(세계관 규칙)가 한 번 언급되면 이후 장면에서도 일관되게 적용돼야 하는데 검증이 없음 | `story.py` 세계관/설정 필드가 회차 전체에 걸쳐 참조되는지 확인. `test_gates.py`에 "설정 일관성" 게이트 추가 검토 | **P1** |
| 왜 노래를 불러야 하는지 개연성 없음 — 구체적 설정이 있다면 나레이션으로 짚어줘야 함 | 사용자에게 안 보이는 내부 설정(왜 그 행동을 하는가)이 장면에 설명되지 않고 생략됨 | `prompts/` — 씬 전환 시 "행동의 이유가 최소 1문장 나레이션으로 드러나야 한다" 규칙 | **P1** |
| 생쥐를 구출하는 핵심 장면(그림+말풍선)이 통째로 빠짐 — 결과(생쥐 안고 있음)만 있고 과정이 없어서 상황 파악에 시간이 걸림 | 콘티/씬 분해 단계에서 "이 장면의 핵심 비트"가 컷 배정에서 누락됨 | `story-harness/webtoon.py` 또는 `story.py`의 씬→컷 분해 로직 — 핵심 액션 비트가 컷 매핑에서 드롭되지 않는지 확인 | **P0** (독자가 이해 못 하는 컷 누락은 스토리 자체가 안 읽힘) |
| "숲의 고대 언어가 은은하게 울려 퍼진다" 등 스토리와 무관한 문장 삽입 | 배경 묘사 생성이 전체 서사 맥락과 분리되어 생성됨 | `prompts/` 배경/나레이션 템플릿 — 직전 컷 맥락을 프롬프트에 더 강하게 전달 | **P2** |

## 3. 콘티 · 연출 피드백

| 피드백 | 원인 추정 | 고칠 위치 | 우선순위 |
|---|---|---|---|
| 1·3컷은 정면인데 2컷만 갑자기 뒷모습 — 독자가 읽는 흐름에 불편함. 앞모습 유지하거나 옆모습 정도의 완만한 전환이 필요 | 컷별 카메라 앵글이 이전/다음 컷과의 연속성을 고려하지 않고 개별 결정됨 | `story-harness/webtoon.py` 또는 `webtoon-harness/scenegen.py`의 컷 앵글 결정 로직 — 인접 컷 앵글 차이가 너무 크면(정면↔후면) 완충 각도를 끼워 넣는 규칙 추가 | **P1** |
| 컷 간 연결이 자연스럽지 않다는 총평("자연스럽게 이어진다는 느낌이 안 난다") | 위와 같은 원인 + 대사/연출 레이어 문제(2번 항목과 연결) | 동일 + `prompts/` 연출 템플릿 | **P1** |

## 5. 긍정 피드백 (같이 챙길 것)

- 배경 품질 전반은 무난 — 문제 없음
- 조명 효과가 신비롭고 예쁘다는 평가 다수
- 동일 인풋 기준 젠툰(경쟁 서비스)보다 결과물이 낫다는 평가
- SD 비율 웹툰은 시장에 없는 포맷이지만 "오히려 특색이 될 수 있다"는 긍정적 반응
- "드디어 웹툰 꼴이 되어가고 있어" — 형식 자체는 자리 잡고 있다는 신호

## 요약

**P0 (지금 이거 없으면 무료여도 못 씀):**
1. 캐릭터 시트 확인 단계 신설 + 시트 단계 원본 반영 정확도 (`charsheet.py`, `stylelock.py`)
2. 소품(무기·모자 등) 일관성 고정 (`charsheet.py`, `scenegen.py`)
3. 이름 등 텍스트 소품의 오타/불일치 제거 (`storyload.py`)
4. 로판 등 장르별 필수 트로프 실제 반영 (`prompts/` 템플릿)
5. 지정 안 한 성격 이탈 차단 (`test_gates.py`에 게이트 추가)
6. 핵심 액션 비트가 컷에서 누락되지 않게 (`webtoon.py`/`story.py` 씬 분해)

**P1 (있으면 확실히 나아짐):** 재현성(시드), 나이대 반영, SD/MD/LD 용어 정리, 텍스트 렌더링, 톤 전환 개연성, 대사 자연스러움, 컷 앵글 연속성

**P2 (완성도, 출시를 막지 않음):** 스티커 평면화, 배경 변주, 포즈, 생성 아티팩트 검수, 장르 추가, 로딩 UX, 비주얼 아이덴티티
