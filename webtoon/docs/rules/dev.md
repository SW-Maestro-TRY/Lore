# 개발 규칙

코드를 고치기 전에 읽습니다. 무엇을 허락 없이 해도 되는지, 고친 뒤 무엇을 확인해야
반영된 것인지를 적었습니다.

## 작업 권한 범위

- **`webtoon/` 과 `haeun/` 안**(하위 전부)은 파일 편집·Bash 명령을 허락 없이 합니다.
  force push · reset --hard · rm -rf 같은 파괴적 명령은 예외로, 항상 확인받습니다.
- **그 바깥**(`comic/` · `common/` · `infra/` · `trailer/` · `apps/` · `build/` · 루트
  파일 등)을 고치거나 그 경로를 대상으로 하는 작업은 **항상 먼저 물어봅니다.**
  허락받고 고쳤으면 커밋과 PR 에 어디를 왜 고쳤는지 남깁니다([commit-pr.md](commit-pr.md)).
- `git push` 처럼 원격에 반영되는 명령은 안쪽이라도 매번 확인받습니다.

## 과금이 걸리는 실행은 매번 따로 승인받습니다

`run.py` 등을 `--dry-run` 없이 돌려 텍스트·이미지 모델을 실제로 부르는 것 전부가
해당합니다. `--dry-run` 으로 되는 점검은 과금이 없으니 자유롭게 하고, 실제 생성으로
넘어가기 직전에 확인받습니다.

**한 번 승인받았다고 다음 단계까지 승인된 것이 아닙니다.** 단계마다 따로 받습니다.
테스트는 기본이 글만이고, 그림 호출은 따로 허락받을 때만 합니다.

### 돌릴 때는 실제로 보여줄 웹툰을 만든다고 생각합니다

과금이 걸린 생성은 "테스트냥이", "테스트용 웹툰" 같은 버리는 입력으로 돌리지 않습니다.
결과물이 그대로 예시 작품·랜딩 샘플(#149)·SNS 소재(#256)로 쓰일 수 있게 만듭니다.

- 매번 **다른 그림체**를 고릅니다. 앞서 돌린 run 과 그림체가 겹치지 않게 합니다.
- 장르·소재·이야기도 매번 다르게 고릅니다.
- 주인공은 사용자가 보고 "나도 이런 걸 만들고 싶다" 고 느낄 만큼 매력적으로 설정합니다.

같은 돈으로 동작 확인과 보여줄 샘플 확보를 한 번에 하려는 것입니다. 승인은 여전히 매번
따로 받고, 승인받은 편수·범위를 넘지 않습니다.

## 화면 코드를 고쳤으면 웹 빌드를 돌린다

`webtoon/fe` 나 `apps/web` 을 고쳤으면 **커밋하기 전에** 저장소 루트에서 돌립니다.

```
npm run build --workspace lore-web
```

`✓ Generating static pages` 까지 가면 통과입니다. 새 워크트리라면 먼저 `npm ci` 를
돌려야 합니다. 1~2분 걸립니다.

**왜 필요한가** — 타입 오류는 이 빌드에서만 걸립니다.

- `npm run dev` 는 연 화면만 컴파일하고 타입 검사를 하지 않아서, 개발 서버에서는
  멀쩡히 보입니다.
- PR 검사(`.github/workflows/contract.yml`)는 마이그레이션 번호와 명세만 보고 웹
  빌드는 돌리지 않습니다. 타입 오류가 있어도 PR 은 초록불로 머지됩니다.
- 그래서 오류는 develop 에 머지된 **뒤** dev 배포에서야 드러나고, 배포 로그는 서버
  출력이 잘려 `exit code: 1` 만 남아서 원인도 안 보입니다.

2026-09-24에 실제로 이렇게 됐습니다. #390 에서 import 한 줄(`IconClose`)을 지웠는데
그 아이콘을 쓰는 곳이 남아 있었고, #391 머지 뒤 dev 배포가 이틀 동안 두 번 실패했습니다
(#397 에서 고침). 배포가 실패했을 때의 대응 순서는 [deploy-failure.md](deploy-failure.md)
에 있습니다.

## 생성 파이프라인(`webtoon/ai`)

### 고쳐도 서버를 다시 띄우기 전까지는 반영되지 않습니다

파이썬은 jar 안에서 실행할 수 없어서, 빌드가 `webtoon/ai` 를 jar 리소스로 담고 서버가
뜰 때 임시 폴더로 풀어(`AiHarnessResources`) 그 사본으로 돌립니다(`HarnessProcess`).

```
webtoon/ai/**  →  (빌드) jar 리소스  →  (기동) 임시 폴더  →  python3 run.py
```

이미 떠 있는 서버는 기동 시점의 사본을 계속 씁니다. 파일만 고쳐 놓고 반영됐다고
판단하면 안 됩니다(2026-09-12에 실제로 이 착각을 함).

### 설정은 코드 기본값에 둡니다

`.env` 는 jar 에 안 담깁니다(키가 실리면 안 되니까). `.env` 에만 있는 설정은 서버에서
통째로 사라집니다. 실제로 모델 선택이 그렇게 사라져서 하네스가 기본값인 gemini 로
붙었다가 키가 없어 이야기 생성이 통째로 실패했습니다. 지금은 `llm.py` 의
`DEFAULT_PROVIDER` 가 기본값을 정합니다.

### 파이썬을 서버로 띄우지 않습니다

옛 프로토타입 웹서버(`landing/serve.py`)는 2026-09-12에 지웠습니다. 자바가 요청마다
파이썬을 자식 프로세스로 부르고, 끝나면 죽습니다.

- **자바가 실행하는 파이썬은 넷뿐입니다** — `run.py` · `character.py` · `stitch.py`
  (new_harness), `s3_upload.py`(upload). 그 밖의 파이썬을 새로 띄우는 구조를 만들지
  않습니다.
- 파이썬 쪽에 웹서버·상태·세션을 다시 만들지 않습니다. 파이썬은 프롬프트를 조립해
  모델을 부르고 결과를 파일로 남기는 CLI 파이프라인이고, 그 바깥(인증·크레딧·DB·
  공개여부·업로드 결과)은 전부 자바가 합니다.

### 하네스를 고칠 때 (harness-is-final)

`story-harness` · `webtoon-harness` 는 **완성본**으로 취급합니다. 2026-09-13에
new_harness 가 실제로 import 하는 파일만 남기고 다 지웠고, 지우기 전 전체를
`haeun/webtoon-ai-backup/` 에 백업했습니다. 이 두 폴더에 파일을 새로 추가하기 전에,
그게 정말 new_harness 가 부르는 것인지부터 확인합니다.

두 폴더 안의 파일을 고칠 때는:

1. 고치기 직전 `<파일>.bak` 백업을 남깁니다.
2. 기존 동작이 그대로 재현되게 **순수 추가**로만 고칩니다. 기본값을 바꾸지 않습니다
   (예: 새 게이트 함수는 새 입력 필드가 없으면 항상 통과시켜서, 예전 run 을 다시 돌려도
   결과가 안 바뀌게 합니다).
3. 고친 뒤 `cd webtoon/ai && python3 test_imports.py` 가 `ALL PASS` 인지 봅니다.
   자바가 실행하는 네 스크립트와 그 의존 전체가 import 되는지 보는 정적 검사이고,
   지금 유일한 회귀 확인 도구입니다. 동작 자체는 검증하지 않습니다.

`new_harness` · `be` · `fe` 는 제품 레이어라 이 제약이 없습니다.

## DB 마이그레이션은 스크립트로 만듭니다

```
./scripts/new-migration.sh webtoon <설명>
```

이 스크립트가 `V<YYYYMMDD>_<HHMM>__webtoon_<설명>.sql` 이름으로 빈 파일을 만들어
줍니다. 파일 이름을 손으로 짓지 않습니다. 규칙 원문은 `common/docs/git-convention.md`
9절입니다.

**왜** — 마이그레이션 폴더는 `apps/api` 와 `webtoon/be` 둘로 나뉘어 있지만 같은 DB 의
같은 `flyway_schema_history` 를 공유합니다. 예전에는 순번(`V12`)을 각자 골라 번호가
겹쳤고, develop 에 머지된 뒤 배포가 "Found more than one migration with version 12"
로 죽었습니다(2026-09-14 #298, 전에도 V11 로 #192). 날짜·시각 번호는 겹칠 일이 없고,
겹치면 PR 검사가 막습니다. 이미 있는 `V1`~`V23` 은 적용된 이력이라 옮기거나 번호를
바꾸지 않습니다.

## 그림 주소와 창고

- **화면에 나가는 그림 주소는 항상 `/images/...` 로 시작하는 상대경로입니다**
  (`PageStore.url()`). 도메인이나 버킷 이름을 코드에 적지 않습니다.
  `lore.webtoon.cdn-base` 설정을 없앤 이유가 그것입니다(2026-09-19).
- **그림은 버킷에 직접 올리지 않고** `PrivateArt`(자바)나 `upload/s3_upload.py`
  (파이썬)를 거칩니다. 그래야 dev 에서는 MinIO 로, 운영에서는 S3 로 알아서 갑니다.
- `lore-contents-046797548177-…` 는 옛 버킷(보관)입니다. 새 코드가 이 이름을 보게
  하지 않습니다.

환경별로 그림이 실제로 어디 있는지는 [local-run.md](local-run.md) 와
`webtoon/docs/server.md` 에, 화면에 그림을 넣는 법은 `webtoon/docs/images.md` 에
있습니다.
