# 병렬 작업 — 워크트리

파일을 고치는 작업을 시작할 때 읽습니다. 같은 저장소 폴더에서 여러 세션이 동시에
돌면 서로의 커밋 안 된 변경이 섞이기 때문에, 작업마다 워크트리를 따로 팝니다.

## 언제 파는가

새 세션에서 파일 수정이 걸린 작업을 맡았고, 지금 위치가 `agent-*` 워크트리가 아니라
원본 저장소(`Lore/`)라면 **조사·수정을 시작하기 전에** 스스로 워크트리를 팝니다.
사용자에게 묻지 않습니다. 팠으면 한 줄로 알립니다(예: "agent-feedback 워크트리에서
작업합니다").

질문에 답하거나 파일을 안 고치는 조사만 하는 세션은 격리할 것이 없으니 생략해도
됩니다.

**왜** — 2026-08-23에 두 세션(정비 작업, 그림체 추가)이 같은 폴더에서 동시에 돌면서
`config.yaml` · `pipeline.py` · `index.html` 에 서로의 커밋 안 된 변경이 섞일 뻔했습니다.
다른 세션이 남의 미커밋 작업을 stash 로 치워 버린 일도 있었습니다(되찾을 때는
`git stash list`).

## 파일별이 아니라 작업별로 나눈다

에이전트를 나누는 기준은 보통 담당 폴더가 아니라 **무엇을 확인하고 고치는가**입니다
("피드백이 반영됐는지 확인하고 고쳐", "비용 트래킹이 빠짐없는지 확인하고 고쳐").
각 에이전트가 필요하면 어디든 고치므로 파일로 경계를 나눌 수 없습니다. 워크트리는
**미커밋 변경이 서로 안 섞이게** 하는 용도로만 씁니다. 각 워크트리 안에는 프로젝트
전체가 그대로 있습니다.

## 쓰는 법

```
# 1. 작업에서 짧은 영문 이름을 뽑는다 (예: "그림 생성 화풍 확인해" → image-style)
# 2. 이미 있는 이름이면 -2, -3 을 붙인다
git worktree list | grep "agent-<이름>"

# 3a. 새 작업이면 develop 최신에서 feature 브랜치로 판다
git fetch origin
git worktree add ../agent-<이름> -b feature/<작업이름> origin/develop

# 3b. 이미 있는 feature 브랜치를 여러 에이전트가 나눠 볼 때는 agent/ 브랜치로 판다
git worktree add ../agent-<이름> -b agent/<이름> feature/<작업이름>
```

그다음부터 이 세션의 모든 읽기·수정·Bash 작업은 `../agent-<이름>/` 에서 합니다.
원본 저장소는 더 건드리지 않습니다.

- 세션 하나 = 워크트리 하나 = 브랜치 하나입니다. 같은 브랜치를 두 워크트리에서 동시에
  체크아웃할 수 없어서 자연히 지켜집니다.
- 새 워크트리에는 `node_modules` 가 없습니다. 웹 빌드 전에 `npm ci` 를 돌립니다.

## `agent/` 브랜치를 feature 브랜치로 합치기 (3b 인 경우)

- **합치기는 원본 저장소 폴더의 세션이 합니다.** feature 브랜치가 거기서 체크아웃돼
  있어서, 워크트리 쪽에서는 git 이 막습니다.
- **합치기는 확인 없이 바로 합니다.** push 전(로컬)이라 원격에 영향이 없고 `git reflog`
  로 되돌릴 수 있습니다. 확인할 검사(웹 빌드, `test_imports.py`)만 통과하면 됩니다.

  ```
  git checkout feature/<작업이름>
  git merge agent/<이름>
  ```

- **충돌이 나면 지우지 않습니다.** 워크트리와 브랜치를 그대로 두고, 어느 파일의 어느
  부분이 충돌했는지 사용자에게 보여 주고 판단을 구합니다.
- 여러 개를 합칠 때는 하나씩 차례로 합칩니다.

## 치우기 전에 결과물부터 옮긴다

```
git worktree remove ../agent-<이름>
git branch -d agent/<이름>
```

**`git worktree remove` 는 그 안의 gitignore 된 것(`work/` · `runs/` · `outputs/` ·
`jobs/`)을 디스크에서 그대로 지웁니다. 휴지통도 안 거치고 복구할 수 없습니다.**
2026-09-12에 테스트 run 들과 그걸로 만든 비교 페이지가 이 한 줄에 통째로 사라졌습니다.
merge 로 가져오는 건 커밋된 코드뿐입니다. 치우기 직전에 남길 결과물이 있는지 보고,
있으면 원본 저장소 쪽으로 복사한 뒤에 지웁니다.

## git 이 안 보는 것 (`work/` · `runs/` · `outputs/` · `jobs/` · `.env`)

이 폴더들은 gitignore 돼 있어서 새 워크트리에서는 **비어서 시작합니다.** 격리가
저절로 되니 기본적으로 안전한 쪽입니다.

- **`runs/` · `outputs/` · `jobs/` 는 심링크로 공유하지 않습니다.** 공유하면 동시쓰기
  충돌이 git 밖에서 다시 생깁니다. 기존 run 을 참고해야 하면 그 run 폴더 하나만
  **복사**합니다.
- **API 키** — 실제 키는 저장소 루트 `.env` 의 `WEBTOON_API_KEY` 하나뿐입니다
  ([local-run.md](local-run.md)). 루트 `.env` 도 새 워크트리에는 없으니, bootRun 을
  띄울 거면 원본 쪽 파일을 심링크합니다. 파이썬을 직접 돌릴 때는 셸에 키를 얹습니다.
- `webtoon/ai/new_harness/.env` 에는 키가 아니라 실험 설정(`NH_STORY_ENGINES` ·
  `NH_STORY_AXES`)이 있습니다. 워크트리에서 같은 설정으로 돌려야 하면 심링크하고,
  아니면 두지 않습니다. 이 파일은 jar 에 안 실려서 서버 동작에는 영향이 없습니다.
