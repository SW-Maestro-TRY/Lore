# 이슈 규칙

이슈를 만들거나, 이슈에 커밋 목록을 달거나, 프로젝트 보드를 정리할 때 읽습니다.
커밋·브랜치·PR 은 [commit-pr.md](commit-pr.md) 에 있습니다.

## 작업 하나에 이슈 하나

`webtoon/` · `haeun/` 작업은 **작업 하나에 이슈 하나, 브랜치 하나, PR 하나**입니다
(2026-08-21부터, 브랜치 규칙은 2026-09-21에 바뀜). 일을 시작하기 전에 GitHub 이슈부터
만듭니다. 이슈가 없는 잡무만 예외입니다.

공유 저장소 전체 컨벤션은 `common/docs/git-convention.md` 에 있고, webtoon 은 거기서
커밋 메시지 부분만 단순화해서 씁니다([commit-pr.md](commit-pr.md)).

## 이슈 제목

- 앞에 타입을 붙입니다: `[Feat]` · `[Fix]` · `[Docs]` · `[Chore]` 등.
- **제목은 명사로 끝냅니다.** "~한다", "~쓴다", "~고친다" 같은 서술형은 쓰지 않습니다.
  목록에서 제목만 훑을 때 서술형은 길고 읽는 리듬을 끊습니다. 본문은 서술형으로
  써도 됩니다 — 이 규칙은 **제목에만** 해당합니다.

  ```
  ✗ [#380] 보존기간이 지난 개인정보를 실제로 파기한다
  ✓ [#380] 보존기간이 지난 개인정보 파기

  ✗ [Feat] 온보딩 FAQ를 실제 동작에 맞게 다시 쓴다
  ✓ [Feat] 온보딩 FAQ를 실제 동작에 맞게 교체
  ```

- 이슈와 PR 은 팀이 읽는 글입니다. 압축·은유 없이 평범한 문장으로 쓰고, 근거는
  `파일:줄` 로 답니다.

## push 한 뒤 이슈에 커밋 목록 달기

**push 할 때마다, 따로 요청이 없어도** 이번에 새로 push 된 커밋을 이슈 번호별로
나눠 관련 이슈마다 댓글을 답니다. 이슈 페이지만 열어도 연결된 커밋을 볼 수 있게
하려는 것입니다.

- 그 이슈에 이미 단 댓글이 있으면 새로 달지 말고, 기존 댓글을 최신 커밋까지
  포함하도록 고칩니다(PATCH).
- **커밋 목록은 `origin/develop` 이 아니라 방금 push 한 브랜치(또는 그 시점의 로컬
  HEAD) 기준으로 뽑습니다.** 피처 브랜치는 develop 에 머지되기 전에도 계속 push
  되므로, develop 기준으로 뽑으면 아직 안 머지된 커밋이 빠집니다(2026-08-21에 실제로
  이 실수를 함).
- 형식은 `` [`sha`](커밋URL) `커밋 메시지` `` 입니다. 메시지를 백틱으로 감싸지
  않으면 `[#18][#19]` 같은 번호를 GitHub 이 전부 이슈 제목 링크로 펼쳐서 댓글이
  못 읽을 만큼 지저분해집니다(2026-08-21에 겪음).

## GitHub 접근은 `gh`

`gh` CLI(`/opt/homebrew/bin/gh`, `haeun9634` 로그인)를 씁니다. `gh` 토큰에는
`project` 스코프가 있고 `git credential fill` 로 꺼내는 토큰에는 없어서, 프로젝트
보드는 `gh` 로만 건드릴 수 있습니다. 헷갈리지 않게 전부 `gh` 로 통일합니다
(`gh api`, `gh api graphql`, `gh project ...`).

## 프로젝트 보드 (`lore`)

이슈 상태는 **`SW-Maestro-TRY` 조직의 `lore` 프로젝트(번호 3)** 에서 관리합니다.
새 프로젝트를 만들지 않습니다.

```
gh project list --owner SW-Maestro-TRY          # lore = 3
gh project field-list 3 --owner SW-Maestro-TRY  # Status 필드 id 확인
```

`Status` 칸(2026-08-23 기준):

| 칸 | 뜻 |
| --- | --- |
| `Backlog` | 아직 손 안 댐 |
| `이번주에 할거` | 이번 주 예정 |
| `이번주 진행중` | 지금 하는 중 (일부 구현됨) |
| `개발된거(Done)` | 개발 완료 |
| `In review` · `Done` | 기본 템플릿에서 남은 칸 — 이 프로젝트에서는 안 씁니다 |

### "이슈 상태 정리해줘" 를 받으면

1. **대상은 `haeun9634` 가 만든 이슈만입니다.** 팀원이 만든 이슈는 건드리지 않습니다
   (`gh api ... --jq '.[] | select(.user.login=="haeun9634")'`).
2. **체크리스트는 이슈 본문이 아니라 코드를 보고 판정합니다.** 이미 찍힌 `[x]` 를
   믿지 말고 실제 구현을 찾아 확인합니다. 근거로 `파일:줄` 을 댈 수 없으면 체크하지
   않습니다.
3. 코드로 확인할 수 없는 항목(디자인 검토, "결과 확인", 실험 정리 등)은 추측해서
   체크하지 않고 그대로 둡니다.
4. 판정에 따라 칸을 옮깁니다.
   - 확인 가능한 항목이 전부 구현됨 → `개발된거(Done)`
   - 일부만 구현됨 → `이번주 진행중`
   - 아무것도 없음 → `Backlog` 유지
5. **이슈를 닫지는 않습니다.** 칸 이동과 체크리스트 갱신까지만 합니다.
6. 기능이 기본값 꺼짐으로 들어가 있어도 제품 화면이 켜고 있으면 구현된 것으로
   봅니다. 그 사실을 근거에 같이 적습니다.

카드 이동은 GraphQL 로 합니다(`gh project item-edit` 도 되지만 item id 를 따로
구해야 하는 건 같습니다).

```
gh api graphql -f query='mutation{ updateProjectV2ItemFieldValue(input:{
  projectId:"<PVT_...>" itemId:"<PVTI_...>"
  fieldId:"<PVTSSF_...>" value:{singleSelectOptionId:"<옵션id>"}
}){ projectV2Item{ id } } }'
```
