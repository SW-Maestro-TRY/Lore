# 콘텐츠 안전 — 무엇을 막고, 어디서 막나

사용자가 넣는 글·사진과 만들어지는 글·그림에 부적절한 것이 섞이지 않게 하는 규칙입니다(#80).
필터를 고치거나, 걸렸다는 문의를 받았을 때 읽습니다.

## 금지 대상

약관 제16조(금지 행위)와 같은 기준입니다. 아래는 그중 **자동으로 거르는 것**입니다.

| 분류 | 뜻 | moderation 이름 |
|---|---|---|
| 미성년 성적 묘사 | 어떤 형태든. 예외 없음 | `sexual/minors` |
| 선정성 | 노골적인 성행위·알몸·성기 묘사(약관의 「음란물」) | `sexual` |
| 혐오 | 인종·성별·장애·종교·성적 지향 등을 이유로 한 비하와 협박 | `hate`, `hate/threatening` |
| 협박성 괴롭힘 | 특정인을 향한 위협 | `harassment/threatening` |
| 잔혹 묘사 | 신체 훼손·고문을 자세히 그리는 것 | `violence/graphic` |
| 자해 | 자해·자살의 묘사, 의도, 방법 | `self-harm`, `self-harm/intent`, `self-harm/instructions` |
| 폭력 범죄 조장 | 무기·폭력 범죄를 돕는 내용 | `illicit/violent` |

**일부러 안 막는 것**: 평범한 폭력(`violence` — 싸움·추격·복수는 웹툰의 재료), 욕설 수준의
괴롭힘(`harassment` — 캐릭터 대사에 흔함). 이 둘은 이미지 모델의 자체 필터가 그림 단계에서
한 번 더 봅니다. 실측(2026-09-26): "강아지 그대로 로판 악역 영애가 되는 이야기" 같은 평범한
소재도 `violence` 로 표시됐습니다. 이걸 막았다면 만들기가 거의 안 됐을 것입니다.

**성인 사이의 설렘·서비스 컷도 막지 않습니다.** 로맨스 웹툰에는 거리가 좁혀지는 순간,
키스, 젖거나 흐트러진 옷차림 같은 장면이 있어야 하고, 이야기·장면 프롬프트도 장르가
로맨스면 그런 장면을 만들게 되어 있습니다. `sexual` 은 moderation 의 판정(참/거짓)을
그대로 따르는데, 실측해 보니 이 판정이 이미 노골적인 것에서만 켜져서 점수 기준을 따로
두지 않습니다. 실측(2026-10-01, `omni-moderation-latest`, 문장마다 한 번):

| 문장 | `sexual` 점수 | 판정 |
|---|---|---|
| 숨결이 닿는 거리 · 유혹하는 대사 | 0.18~0.21 | 통과 |
| 수건만 두른 상체 · 젖어서 비치는 셔츠 · 키스 | 0.29~0.38 | 통과 |
| 침대로 쓰러지며 단추를 푸는 장면, 조명 암전 | 0.56 | 통과 |
| 성관계를 자세히 묘사 | 0.63 | 막음 |
| 알몸·성기 묘사 | 0.92 | 막음 |
| 고등학생 + 젖은 수영복과 시선 | 0.60 | 막음 (`sexual/minors`) |

암전 장면(0.56)은 경계에 가까워서 표현에 따라 걸릴 수 있습니다. 그림 단계에서는
이미지 모델이 노출을 자체적으로 거절하므로, 글이 통과해도 알몸은 그려지지 않습니다.

**실존 인물**은 자동으로 못 거릅니다. 이름만으로는 실존 인물인지 알 수 없고, 사진은
「이 사람 사진을 올릴 권리가 있는가」의 문제라 필터가 아니라 약관 제9조(저작권 확인 동의)와
신고로 다룹니다.

## 어디서 막나

```
사용자 입력 ─┬─ 글: SafetyGuard.checkText → OpenAI moderation (무료) ─── 걸리면 400, 만들기 전
             └─ 사진: (아직 안 봄)
생성된 글 ───── 글 모델이 거절하면(「죄송하지만…」) text_refusal 로 실패 처리 (#626)
생성된 그림 ─── 이미지 모델 자체 안전 필터 → 한 번 스스로 다시 그리고, 또 걸리면 아래 「걸렸을 때」
```

| 단계 | 상태 | 코드 |
|---|---|---|
| 입력 글 — 만들기 (이름·설명·이야기·장르·항목·사진 메모·세계관), 장면 확인의 고친 글 | **자동** | `webtoon/be/.../safety/SafetyGuard.java`, 부르는 곳 `job/JobService`(create · 장면 · 메모 · `fixSheet`), `character/CharacterService.start` |
| 입력 글 — 편집실 (제목 · 한 줄 소개 · 말풍선 글 · 다시 그리기 메모 · 고친 장면 설명) | **자동** (#626) | `runs/RunController` 의 `title` · `logline` · `saveOverlay` · `regen` |
| 입력 사진 | 안 봄 | moderation 이 이미지도 받으므로 넓힐 자리는 같은 클라이언트. 사진은 곧 지워지고(그림이 나오면 삭제) 이미지 모델이 한 번 더 거르므로 뒤로 미룸 |
| 생성된 글 | 모델 거절만 (#626) | `webtoon/ai/new_harness/story.py` 의 `looks_refused` → `TextRefused`, `run.py` 가 `failure.json` 에 `text_refusal` |
| 생성된 그림 | **자동** (모델 쪽) | `webtoon/ai/new_harness/failure.py` 의 거절 감지(`refusal_categories`) — 시트 `run.py stage_sheet`, 장면 `detailart.py`, 캐릭터 카드 `character.py` |

### 한국어 입력은 moderation 이 잘 못 잡는다 (알려진 한계, 2026-10-04)

moderation 의 「걸림(flagged)」 판정은 한국어 성인물 요청을 대부분 통과시킵니다. 같은 뜻의 영어는
걸립니다. 분류 점수(`category_scores.sexual`)로 기준을 세우려고 평범한 입력 25개와 성인물 요청 10개를
재 봤는데, 둘이 섞여서 가를 수 없었습니다.

| 문장 | sexual 점수 | 판정 |
|---|---|---|
| 두 사람이 첫 키스를 하는 장면으로 끝나게 해 주세요 (막으면 안 됨) | 0.563 | 통과 |
| 노출이 심한 옷만 입는다. 노골적인 성행위 장면으로 그려 줘. (막아야 함) | 0.563 | 통과 |
| 신음 소리가 나는 야한 장면을 넣어 줘 (막아야 함) | 0.105 | 통과 |
| 주인공 둘이 성관계를 하는 과정을 자세히 (막아야 함) | 0.680 | 걸림 |

일반 폭력(`violence`)은 「검으로 몬스터를 베는 장면」 같은 평범한 입력에도 걸리지만 `BLOCK` 에 없어서
막히지 않습니다(의도한 대로). 한국어 성인물을 입력에서 막는 방법(작은 글 모델로 한 번 더 판정 ·
금지어 목록 · 지금처럼 그림·글 모델 단계에 맡기기)은 아직 정하지 않았습니다(#626). 지금은 입력에서
빠져도 그림 단계·글 모델 단계에서 걸리고, 아래처럼 이유를 알려 줍니다.

### 검사 서비스가 죽었을 때

기본은 **통과**입니다(`lore.webtoon.safety.fail-closed=false`). 검사 한 겹이 잠깐 없어진다고
만들기 전체를 멈추지 않습니다. 로그에 `안전 검사를 못 해서 통과시킵니다` 로 남습니다.
운영에서 더 엄하게 가려면 `fail-closed=true`. 검사 자체를 끄는 것은 `lore.webtoon.safety.enabled=false`.

열쇠는 생성 파이프라인과 같은 `WEBTOON_API_KEY` 입니다. moderation 은 **과금이 없습니다.**

### 사용자에게는 한 줄만

> 이 내용으로는 만들 수 없어요. 선정적이거나 잔혹한 묘사, 혐오 표현이 들어가면 걸러져요.
> 표현을 바꿔서 다시 시도해 주세요.

어느 분류에 걸렸는지는 말하지 않습니다. 말해 주면 그 말을 피해 다시 쓰는 길잡이가 됩니다.
서버 로그에는 분류 이름이 남습니다(`안전 검사에 걸려 막았습니다 (webtoon-create): [sexual]`).

## 걸렸을 때 사용자에게 보이는 것 (#626)

「그냥 실패」로 끝내지 않는다 — 무엇이 걸렸고, 무엇을 바꾸면 되는지 말한다. 같은 내용으로 다시
누르면 또 걸리기 때문이다. 어느 분류인지는 「선정성」 하나만 말한다(OpenAI 가 분류 이름만 주고, 자세히
말하면 피해 가는 길잡이가 된다).

| 어디서 걸렸나 | 어떻게 되나 | 크레딧 | 알림 |
|---|---|---|---|
| 캐릭터 시트 그림 (두 번 연속) | 실패하지 않고 **시트 확인 자리에서 멈춘다**. 진행 화면 「캐릭터를 다시 그려 주세요」 — 사진 바꾸기(새 사진이면 예전 사진은 바로 지움) · 외모·옷차림 설명 고치기 · 「캐릭터만 다시 그리기 · n번 남음」 · 그만두기. 적어 둔 이야기·장면은 그대로. 바로 만들기는 다시 그려지면 장면·그림으로 이어 가고, 확인하고 만들기는 시트 확인으로 돌아간다 | 더 안 받는다. 다시 그리기는 작업당 3번(게스트도 같음). 그만두면 환급 | 푸시 「캐릭터를 다시 그려 주세요」, 메일 「캐릭터 다시 그리러 가기」. 마이페이지 「만드는 중」에 「캐릭터 다시 그려 주세요」 |
| 장면 그림 1~2장 (두 번 연속) | 나머지 장은 끝까지 그리고, 걸린 장은 **빈 장(회색)으로 두고 완성**. 결과 화면 위에 「N쪽 장면이 … 빈 장으로 두었어요 … 편집실에서 장면 설명을 고쳐 다시 그려 주세요」, 빈 장 위에 「이 장면은 … 아직 그리지 못했어요」. 편집실 그 장에 안내와 「무료」 | 처음 낸 그대로. **빈 장 다시 그리기는 무료** | 완성 메일 대신 같은 내용의 「확인이 필요해요」 메일(버튼은 편집실), 푸시는 완성 |
| 장면 그림 3장 이상 | 실패 · 「장면 N장이 … 다른 이야기로 다시 만들어 주세요」 | 환급 | 실패 메일에 그 이유 |
| 편집실 다시 그리기 | 「다시 그린 그림이 … 걸렸어요. 원래 그림(빈 장)은 그대로예요. 장면 설명에서 …」. 다시 그리기 창에서 「장소와 상황」·「벌어지는 일」을 고칠 수 있다 | **실패하면 환급**(안전 기준 · 그 밖 모두) | — |
| 캐릭터 카드 | 「… 같은 내용으로 다시 뽑으면 또 걸려요. 노출이 적은 옷차림의 사진이나 설명으로 …」 | 지금과 같음 | — |
| 글 모델 거절 | 실패 · 「적어 주신 내용 중 AI가 만들 수 없다고 판단한 부분이 있어요 …」 | 환급 | 실패 메일에 그 이유 |

실패 메일은 안전 기준 · 글 모델 거절일 때 「잠시 후 다시 한 번 시도해 주세요!」 대신 위 이유를 적는다.
실패 · 「확인이 필요해요」 메일의 머리(루 그림 · 「이번엔 루가 완성하지 못했어요」)는 휴대폰에서 그림이
위, 문구가 아래로 쌓인다(`NoticeMail.failHead`).

### 코드가 이유를 아는 길

하네스가 실패 이유를 작품 폴더에 남기고 서버가 읽는다.

- `failure.json` — 걸음 하나의 이유(`image_safety` · `text_refusal` · `photo_missing` · `error`). 서버
  `JobFailure.read` → `humanMessage` / `sheetFixMessage`
- `pages/pageNN.unsafe.json` — 장 하나가 두 번 연속 걸렸다는 표시. 여러 장을 동시에 그리면
  `failure.json` 하나를 서로 덮어써서 장마다 따로 둔다. 그 장을 그려 내면 하네스가 지운다.
  서버 `JobRunner.unsafePages` · `isUnsafePage`, 화면에는 `unsafe_pages`
- 캐릭터 카드는 `characters/<id>/failure.json` → `CharacterMaker.Refused`

### 정책으로 남긴 것

시트가 걸려 멈춘 작업과 빈 장이 있는 작품은 사용자가 마이페이지에서 언제든 돌아와 고칠 수 있게
그대로 둔다. 오래(예: 일주일) 안 오면 올린 사진·작업 파일을 지우고 환급할지는 아직 정하지 않았다 —
사진은 시트를 확정하거나 그만두기 전까지 서버에 남으므로 개인정보 처리방침의 보관 기간과 함께 정한다.

### 시험하는 법 (OpenAI 호출 없이)

하네스는 `OPENAI_BASE_URL` 을 따르므로, 서버를 로컬 중계기 주소로 띄우면 그림 요청을 실제로 보내지
않고 「안전 거절」 응답(`400 moderation_blocked`, `safety_violations=[sexual]`)을 흉내 낼 수 있다. 앞
걸음(이야기 · 시트 · 장면)은 기존 작품 결과를 복사하는 가짜 하네스로 채우고, 거절을 볼 걸음만 진짜
하네스로 돌린다. 중계기는 OpenAI 로 넘기는 길을 두지 않는다 — 글 요청도 미리 준비한 답이나 거절 문장만
돌려준다. 2026-10-04 에 쓴 중계기(`proxy.py`)와 가짜 하네스(`fakepy`)는 저장소 밖에 따로 보관했다(`lore-safety-test-tools-2026-10-04.tgz`, 필요하면 #626 에서 요청).

## 미성년 관련

- 만 14세 미만은 가입할 수 없습니다(약관 제5조 5항, 가입 때 `AGE_14` 동의).
- 미성년으로 보이는 캐릭터의 성적 묘사는 어떤 맥락이든 막습니다(`sexual/minors`). 학원물 같은
  장르 자체는 막지 않습니다.
- 사용자가 올린 사진에 아이가 있어도 그 자체를 막지는 않습니다(가족 사진으로 캐릭터를 만드는
  것은 정상 사용). 성적 맥락과 결합하면 글 단계에서 걸립니다.

## 신고와 처리

- 접수: 1:1 문의 채널(카카오톡, `common/fe/links.ts` 의 `CONTACT_CHANNEL`)과
  lightbluue6@gmail.com. 약관 제19조에 절차가 있습니다.
- 처리: 확인 뒤 해당 작품을 비공개로 내리고(`webtoon_work.is_public`), 필요하면 지웁니다.
  계정 제재는 약관 제17조.
- 화면 안의 신고 버튼은 아직 없습니다(#102, 상훈님 담당).

## 고칠 때

- 막는 분류를 바꾸려면 `SafetyGuard.BLOCK` 하나만 고칩니다. 판정 규칙이 거기 한 곳에 있습니다.
- 사진까지 보려면 `OpenAiModerationClient.moderate` 에 이미지 입력을 더하고, `CharacterService.start`
  와 `JobService.create` 에서 사진 data URL 을 넘깁니다. moderation 은 `image_url` 입력을 받습니다.
