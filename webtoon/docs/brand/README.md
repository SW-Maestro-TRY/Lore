# LORE — 서비스를 뭐라고 소개하나

소개서·랜딩·광고·온보딩·기업 협업·발표 문구를 쓰거나 고칠 때 먼저 읽습니다. 이 폴더가 기준입니다.

## 1. LORE 는 무엇인가

| | |
| --- | --- |
| 서비스 정의 | LORE 는 내 캐릭터와 세계관, 곧 개인 IP 가 이야기 속에서 살아 움직이게 하는 AI 창작 플랫폼입니다. **지금은 만화로 보여 줍니다.** |
| 풀어서 | 사용자는 캐릭터를 가져옵니다. 세계관과 이야기까지 가져올 수도 있고, 캐릭터 하나만 있어도 됩니다. LORE 는 그 캐릭터를 사건 속에 넣고, 적힌 성격 그대로 행동하고 말하고 관계를 맺는 모습을 만화로 만들어 줍니다. |
| 한 문장 | 내가 만든 캐릭터와 세계가, 상상 속에서 현실의 콘텐츠로. |
| 웹툰 제품 | LORE 웹툰은 내 캐릭터가 사건 속에서 살아 움직이는 모습을 만화로 만드는 AI 웹툰 스튜디오입니다. 사건을 LORE 가 준비하면 **세계관 체험**, 사용자가 준비하면 **웹툰 만들기**입니다. 세계관 만들기는 두 경험이 함께 쓰는 창작 도구입니다. |
| 개인 IP 란 | 캐릭터만이 아니라 창작자가 만든 캐릭터·세계관·인물 관계·이야기까지. 다만 전부 가질 필요는 없고, **캐릭터 하나만 있어도 시작할 수 있습니다.** |

이 표의 문장이 기준입니다. [message.md](message.md)·[lore.md](lore.md)의 정의 줄은 이 표를 그대로 옮긴 것이고, 다른 문장을 새로 만들지 않습니다.

「플랫폼」을 말할 때는 「지금은 만화」를 바로 붙입니다. 연재 플랫폼으로 듣거나 과하게 들리지 않게 하기 위해서입니다. 「다양한 콘텐츠」는 정의 문장에 넣지 않습니다. 차별점은 콘텐츠 종류가 아니라 개인 IP 가 살아 움직인다는 것이고, 콘텐츠가 넓어질 여지는 「지금은 만화」 한 마디에 이미 들어 있습니다.

## 2. 핵심 가치

| 층 | 핵심 가치 | 핵심 감정 |
| --- | --- | --- |
| LORE 전체 | 내 개인 IP 가 사건 속에서 살아 움직이는 경험 | 「진짜 내 캐릭터라면 이럴 것 같아!」 + 「내가 상상한 세계가 실제로 구현됐어!」 |
| 세계관 체험 | LORE 가 준비한 사건 속에서 내 캐릭터가 살아 움직인다 (개인 IP 중 캐릭터) | 「진짜 내 캐릭터라면 이럴 것 같아!」 |
| 웹툰 만들기 | 내가 준비한 사건 속에서 내 캐릭터와 세계가 작품이 된다 (개인 IP 전체) | 「내가 상상한 세계가 실제로 구현됐어!」 |
| Zzal (캐릭터 키우기) | 내 캐릭터를 곁에 두고 키우는 경험 | 상훈 영역. [lore.md](lore.md) |

LORE 전체를 「캐릭터 체험 서비스」로 좁혀 말하지 않습니다. 체험은 캐릭터에 집중한 경험이고, 웹툰 만들기는 개인 IP 전체를 쓰는 창작 경험입니다.

| 구분 | 뜻 |
| --- | --- |
| 가치 전달 방식 | 사건·인물과의 상호작용, 이야기, 시각적 콘텐츠(지금은 만화) |
| 핵심 기술 | 캐릭터다움 재현, 설정 보존, 이야기 생성 |
| 품질 조건 (기반) | 캐붕 방지, 세계관 일관성, 서사 개연성. 기준은 [../story-principles.md](../story-principles.md) |

설정 보존은 파는 물건이 아니라 핵심 가치를 떠받치는 기술적 기반입니다. 사용자가 보존율이라는 숫자를 얻으려고 오지는
않지만, 설정이 무너지면 살아 움직인다는 경험도 깨집니다.

## 3. 경험 둘, 그리고 둘이 함께 쓰는 창작 도구

**두 경험을 가르는 기준은 하나, 사건을 누가 준비하느냐입니다.** 세계관 체험은 LORE 가 세계·등장인물·사건을 준비하고 사용자는 캐릭터만 가져옵니다. 웹툰 만들기는 사용자가 자기 세계관과 이야기로 사건을 준비합니다. 둘 다 「내 캐릭터가 사건 속에서 살아 움직인다」는 같은 경험이고, 가벼운 판과 무거운 판이 아닙니다. 사용자에게는 「캐릭터만 있으면 우리 사건으로, 세계관까지 있으면 네 사건으로」 한 마디로 설명합니다.

세계관 체험과 웹툰 만들기는 사용자가 얻으려는 **경험**이고, 세계관 만들기는 그 두 경험에 쓰는 **창작 도구**입니다. 같은 종류의 기능이 아닙니다.

```
LORE — 개인 IP 가 이야기 속에서 살아 움직인다
  ├ 세계관 체험   내 캐릭터가 다른 세계 · 사건에서 살아 움직이는 모습을 본다
  ├ 웹툰 만들기   내 캐릭터 · 세계관 · 이야기를 작품으로 만들고 1화 · 2화 · 3화로 잇는다
  └ 공통 창작 자산 내 캐릭터 · 내 세계관(세계관 만들기) · 설정 · 인물 관계
```

| 영역 | 역할 | 자리 |
| --- | --- | --- |
| 세계관 체험 | LORE 가 준비한 사건에서 내 캐릭터가 살아 움직이는 경험 | 1순위 경험 |
| 웹툰 만들기 | 내 IP 를 긴 작품으로 구현 | 2순위 경험 |
| 세계관 만들기 | 두 경험에 쓸 설정(캐릭터 · 장소 · 인물 관계 · 사건)을 만들고 관리 | 공통 창작 도구 |

세계관 만들기로 만든 세계는 체험 공간이 되기도 하고(다른 사람이 자기 캐릭터를 넣어 본다), 웹툰 만들기의 설정으로도 쓰입니다. 따로 들어가서 쓸 수도 있지만, 제품 구조에서는 두 경험을 받치는 기반입니다.

| | 세계관 체험 | 웹툰 만들기 |
| --- | --- | --- |
| 사건을 누가 준비하나 | LORE (세계·등장인물·사건) | 사용자 (내 세계관·내 이야기) |
| 한 줄 | 내 캐릭터를 다양한 세계에 퐁당! | 내가 만든 세계와 이야기를 작품으로! |
| 핵심 질문 | 내 캐릭터가 이 세계에 들어간다면 어떻게 될까? | 내가 만든 세계와 이야기가 실제 웹툰이 된다면? |
| 핵심 욕구 | 내 캐릭터가 살아 움직이는 모습을 보고 싶다 | 내 세계관과 이야기를 작품으로 보고 싶다 |
| 제공 경험 | 흥미로운 세계·사건·등장인물이 준비돼 있고, 내 캐릭터를 넣으면 그 성격과 가치관대로 사건 속에서 행동하고 인물들과 얽힌다 | 내가 만든 캐릭터·세계관·이야기를 바탕으로 서사를 구성하고 시각화한다. 결과를 확인하고 고치며, 설정과 사건의 연속성을 유지한 채 이어 간다 |
| 만족 순간 | 「진짜 내 캐릭터라면 이럴 것 같아!」 | 「내가 상상한 세계가 실제로 구현됐어!」 |
| 반복 동기 | 다른 상황·다른 세계에서도 내 캐릭터다운 모습을 발견하고 싶다 | 다음 이야기도 작품으로 만들고 싶다 |
| 사용자가 가져오는 IP | 캐릭터 | 캐릭터·세계관·서사 |
| 살아 움직이는 대상 | 캐릭터의 행동과 관계 | 캐릭터와 세계관, 이야기 전체 |
| LORE 가 주는 것 | 세계·사건·등장인물, 그 안의 새로운 상호작용 | 서사 구성·시각화·연속성(설정집·진행 상태) |
| 만족의 기준 | 내 캐릭터답고 재미있는가 | 내 세계와 이야기가 의도대로 구현됐는가 |
| 결과물 | 지금은 사건에 내 캐릭터가 들어간 장면을 만화로 | 1화, 2화, 3화로 이어지는 연재 |

둘은 같은 가치를 다른 길로 얻는 경험입니다. 체험이 짧은 만화로 끝나야 한다거나 반드시 웹툰 연재로 이어져야 한다는 규칙은 두지 않습니다. 그 연결은 사용자 경험을 설계하면서 정합니다. 세계관을 가진 사람은 처음부터 웹툰 만들기로 들어옵니다. 둘은 캐릭터 라이브러리·설정집(세계관)·
시트·편집실을 공유합니다. 체험의 화면 순서는 [experience.md](experience.md).

**원래 흐름과 비교하지 않습니다.** 「내 캐릭터가 들어와서 원래 이야기가 이렇게 달라졌다」는 사용자가 그 원래 이야기를 아는 작품(해리포터처럼)에서만 뜻이 있습니다. LORE 가 만든 세계를 처음 보는 사용자에게는 비교할 기준이 없습니다. 사용자가 아는 것은 자기 캐릭터이므로, 보여 줄 것은 「얘라면 진짜 이렇게 했겠다」 하나입니다. 처음 보는 세계도 사건 한 장으로 끌리고 이해되게 하는 것이 체험의 UX 과제입니다.

**세계관 체험이 있는 이유.** 캐릭터는 있지만 보여 줄 이야기나 세계관이 없는 자캐러에게 「웹툰 한 편을 만들어
보세요」는 부담이고, 「내 캐릭터가 이런 상황에 들어가면 어떻게 할까」라는 작은 호기심을 풀려고 이야기 생성·장면
구성·그림까지 기다리는 것은 과합니다. 체험은 사용자가 이야기를 준비하지 않아도 LORE 가 준비한 사건에 캐릭터를
넣어 그 캐릭터다운 새 모습을 발견하게 합니다. 웹툰의 축소판이 아닙니다. 체험은 **핵심 가치에 가장 쉽게 닿는 길**이고, 자캐러가 반복해서 쓰는지는 운영 지표(같은 캐릭터로 다른 사건·세계 재방문)로 봅니다.

## 4. 사용자 흐름

```
LORE 첫 방문 — 내 캐릭터와 세계가 살아 움직이는 곳
  어떤 경험을 하고 싶나요?
  ├ 세계관 체험: 세계관 고르기 → 그 안의 사건 고르기 → 내 캐릭터 고르기 → 만화 → 다른 사건·다른 세계에 또 넣기
  └ 웹툰 만들기: 캐릭터 · 이야기(· 내 세계관) → 이야기 구성 → 웹툰 제작·편집 → 다음 화
  두 경험 모두 → 세계관 만들기(캐릭터 · 장소 · 인물 관계 · 사건)를 가져다 쓸 수 있다
```

## 5. 타깃과 우선순위

| 구분 | 누구 | 경험 |
| --- | --- | --- |
| 1차 핵심 타깃 | 자기 캐릭터가 있고, 그 캐릭터가 다양한 상황에서 어떻게 행동할지 보고 싶은 자캐 창작자. 세계관까지 쓰지 않아도 된다 | 세계관 체험 · 캐릭터 키우기 |
| 확장 타깃 | 자기 세계관과 서사가 있고, 이를 웹툰으로 만들거나 연재하고 싶은 창작자. 웹소설 작가 포함 | 웹툰 만들기 · 세계관 만들기 |
| 유입 타깃 | 최애·반려동물·내 사진을 새 세계에 넣어 보고 싶은 사람. 「우리 강아지가 황궁에 떨어진다면?」 | 세계관 체험 |
| 독자 | 공개된 작품을 읽고 댓글·구독하는 사람 | — |

소개하는 순서도 세계관 체험이 먼저, 웹툰 만들기가 다음입니다. 세계관 만들기는 두 경험이 함께 쓰는 도구로 소개합니다. 자세한 타깃은 [target.md](target.md).

## 쓸 때 지킬 것

- 「플랫폼」 뒤에는 「지금은 만화」를 붙입니다. 「다양한 콘텐츠」를 차별점으로 말하지 않습니다. 차별점은 개인 IP 가 살아 움직인다는 것입니다.
- 「개인 IP」는 정의·심사·사업 소개·확장 타깃 줄에 씁니다. 유입 광고·화면 문구는 「내 캐릭터」로 말합니다(반려동물·최애·내 사진은 IP 가 아님).
- 캐릭터 챗봇으로 들리게 쓰지 않습니다. 사용자는 말을 거는 사람이 아니라 넣고 보는 사람입니다.
- 유명 작품의 세계·인물은 프리셋으로 쓰지 않습니다. 오리지널 또는 권리가 정리된 세계만.
- 날짜가 있는 수치는 그 날짜와 함께. 운영 실측과 개발 중인 코드 상태를 섞지 않습니다. 원가·크레딧 숫자는 대외 자료에 쓰지 않습니다.
- Zzal(캐릭터 키우기)·Piece Maker 를 웹툰의 기능처럼 쓰지 않습니다.
