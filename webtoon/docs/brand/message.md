# 무엇이라고 말하는가

2026-09-27 정리. 한 문장으로 모든 걸 설명하려 하지 않고, 층마다 역할을 나눕니다.

LORE는 웹툰을 만드는 서비스입니다. 그 웹툰이 사용자에게 주는 것을 설명할 때는
"사용자의 창작물을 시각적인 이야기로 바꿔 준다"를 기준 문장으로 씁니다.

| 층 | 문장 | 쓰는 곳 |
| --- | --- | --- |
| 핵심 경험 | 내 캐릭터가 이야기 속에서 살아 움직이는 순간. | 소개서 표지·마지막 장, 랜딩 상단 |
| 제품 정의 | LORE는 내가 가진 캐릭터와 이야기를 바탕으로 한 편의 웹툰을 만들어 주는 AI 웹툰 스튜디오입니다. | 서비스 정의, 첫 설명 |
| 핵심 기능 | 캐릭터 생성 + 웹툰 생성. 캐릭터 제작은 웹툰으로 들어오는 입구이고, 웹툰 제작이 핵심 기능입니다. | 제품 구조, 기능 설명 |
| 구조 | 캐릭터 → 이야기 → 웹툰 | 흐름 설명 |
| 차별점 | 캐릭터를 웹툰으로 만드는 게 아니라, 캐릭터의 이야기를 웹툰으로 만듭니다. | 포지셔닝 |
| 가치 | LORE는 웹툰으로, 사용자의 창작물을 시각적인 이야기로 바꿔 줍니다. | 서비스 정의 아래, 핵심 경험 장, 마지막 장 |
| 광고 | "만약 내 ○○가 ○○라면?" → 실제로 만들어 본 웹툰을 보여 준다 | 유입 광고 |

## 웹툰의 역할

웹툰은 사용자의 상상과 창작물을 시각적인 이야기로 보여 주는 매체입니다. 연재할 수
있을 만큼 완벽한 작품을 만드는 것이 목표가 아닙니다.

- 유입 타겟이 기대하는 것은 "진짜 우리 강아지가 로판 여주가 됐네"라는 순간입니다.
- 메인 타겟은 한 단계 더 나아가 "내가 만든 캐릭터가 진짜 이렇게 행동하네"를
  경험합니다.

그래서 결과물을 설명할 때는 그림의 완성도보다, 내 캐릭터가 이야기 속에서 무엇을
했는지를 먼저 보여 줍니다.

## 제품 가치와 광고 훅

둘은 같을 필요가 없습니다.

| | 전달할 것 | 예 |
| --- | --- | --- |
| 제품 · 브랜드 | 내 창작물이 살아 있는 이야기로 구현된다 | 내 캐릭터가 이야기 속에서 살아 움직이는 순간. |
| 광고 | "어? 이거 해 보고 싶은데?" | 만약 내 최애가 마법학교에 간다면? → "직접 만들어 봤습니다" → 실제 웹툰 |

광고에서는 "웹툰으로 만들어 준다"는 것 자체가 좋은 훅입니다. 상상 하나를 던지고,
실제로 만든 웹툰을 결과로 보여 줍니다.

## 기능을 사용자 가치로 옮길 때

| 기능 설명 | 사용자에게 하는 말 |
| --- | --- |
| 캐릭터 시트로 일관성을 유지 | 첫 장면의 캐릭터가 마지막 장면까지 같은 캐릭터로 |
| 사람이 아닌 대상을 의인화하지 않음 | 넣은 대상을, 그 모습 그대로 이야기 속으로 |
| 이야기 후보 중 고르기(2번 확인하며) | 결과만 받는 게 아니라, 이야기 방향을 내가 고른다 |

## 소개서를 쓸 때

- 순서는 무엇(핵심 경험·정의) → 왜(문제) → 누구(메인 타겟·유입 타겟) → 어떻게
  (캐릭터 → 이야기 → 웹툰) → 결과물 순입니다. 기능 설명부터 시작하지 않습니다.
- 감성 문구만 있는 자료가 되지 않게, 캐릭터 만드는 시간·한 편 시간·한 편 분량 같은
  실제 정보는 앞쪽에 남깁니다. 숫자는 [features-now.md](features-now.md)의 실측값을
  씁니다.
- 그림체 목록, 비용과 원가, 경쟁 비교, 긴 FAQ, 정부지원 설명은 필요하지만 뒤로
  보냅니다. 원가는 대외 자료에 넣지 않습니다.
- 더 크게 보여 줄 것: 내 캐릭터, 이야기, 캐릭터가 실제로 행동하는 모습, 첫 컷과
  마지막 컷이 같은 캐릭터라는 점, 완성된 웹툰, 누구를 위한 서비스인지.
