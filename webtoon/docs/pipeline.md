# 웹툰 한 편이 만들어지는 순서와 단계별 모델

> 2026-10-04 기준. 근거는 코드 기본값(`webtoon/ai/new_harness/run.py --plan`), 실제 작품 기록(작품 폴더의
> `meta.json` — 호출마다 단계·모델이 남는다), 환경별 설정 확인(로컬 · dev · 운영)이다. 단계·모델을 바꾸면
> 이 문서도 같이 고친다.

## 한눈에

```
                         ┌─ 이야기 쪽 (글) ───────────────────────────────┐
만들기 누름 ─ 입력 검사 ─┤  주인공 페르소나 · 얽힐 인물 → 이야기 후보 4개 → 이야기 검수 ├─ 이야기 고르기
                         └─ 캐릭터 시트 쪽 (나란히) ─ 시트 사양 → 시트 그림 ─────────────┘
                                                                     │
   ← 확인하고 만들기면 여기서 사람이 고른다(인물 · 이야기 · 시트)    ▼
                                                               장면 나누기
                                                                     │
   ← 확인하고 만들기면 여기서 장면을 확인 · 고친다                  ▼
                                   장마다 동시에: 그림 → 장 검수 (걸리면 그 장만 다시 그림)
                                                                     │
                                                                     ▼
                                       화 전체 검수 (걸린 장을 다시 그림, 최대 3바퀴)
                                                                     │
                                                                     ▼
                                                 이어 붙이기 · 올리기 · 완성 알림
```

## 단계별 모델

로컬 · dev · 운영 모두 **코드 기본값 그대로** 돈다. 세 환경 다 설정은 `NH_PROVIDER=openai` 하나뿐이고 단계별
모델을 덮어쓰는 값은 없다(2026-10-04 확인 — 로컬 `.env`, dev 박스 `.env`, 운영 `/etc/lore/lore.env` ·
Parameter Store). 모델은 전부 OpenAI 다.

| 순서 | 단계 (기록에 남는 이름) | 하는 일 | 모델 | 몇 번 |
|---|---|---|---|---|
| 0 | 입력 검사 | 사용자가 적은 글이 성인물 · 혐오 · 잔혹물인가 | `omni-moderation-latest`(무료) + 한국어 금지어 | 만들기 · 고치기마다 |
| 1 | `PERSONA` | 사용자가 적은 캐릭터로 주인공 카드 | **gpt-5.1** | 1 |
| 1 | `CAST` | 주인공과 얽힐 인물 넷 | **gpt-5.1** | 1 (PERSONA 와 동시) |
| 2 | `STORY` | 이야기 후보 4개 | **gpt-5.1** | 1 · 다시 짓기마다 1 |
| 3 | `STORY_REVIEW` | 이야기 후보 검수 — 고르기 전에 후보마다 어디서 걸리는지 | gpt-4.1 | 1 |
| 1~2 와 동시 | `SHEET` | 캐릭터 시트 사양(사진 · 설명 → 글) | gpt-4.1 | 1 · 다시 그리기마다 1 |
| 1~2 와 동시 | `SHEET_IMAGE` | 캐릭터 시트 그림 | **gpt-image-2** | 1 (안전 기준에 걸리면 스스로 1번 더) |
| 4 | `SCENE` | 고른 이야기를 장면으로 나누기(장면마다 장소 · 벌어지는 일 · 나레이션) | **gpt-5.1** | 1 |
| 5 | `PAGE_IMAGE` | 장 그림(표지 1장 + 장면 수) | **gpt-image-2** | 장 수 + 다시 그린 수 |
| 5 | `PAGE_REVIEW` | 장 검수 — 장마다 그린 직후 | gpt-4.1 | 표지 뺀 장 수 + 다시 그린 수 |
| 5 | `COVER_REVIEW` | 표지 검수 — 칸 하나 · 글상자 없음 · 제목 그대로 | gpt-4.1 | 1 + 다시 그린 수 |
| 6 | `FULL_REVIEW` | 화 전체 검수 — 다 그린 뒤 처음부터 끝까지 한 번에 | **gpt-5.1** | 1 ~ 3 |
| 옵션 | `CAST_SHEET` · `CAST_SHEET_IMAGE` | 조연 시트(사양 · 그림, 크레딧 1) | gpt-4.1 · gpt-image-2 | 사람이 누를 때 |
| 끔 | `STORY_DIFF` | 후보 넷이 서로 다른가 | gpt-4.1 | 기본 꺼짐(`NH_STORY_DIFF`) |

실제 기록 예 — 「카페 사장에게는 비밀이 많다」(20261003T133334-b5ccce, 서버로 만든 9장짜리):
PERSONA · CAST · STORY · SCENE · FULL_REVIEW 각 1번(gpt-5.1), SHEET · STORY_REVIEW · COVER_REVIEW 각 1번 ·
PAGE_REVIEW 8번(gpt-4.1), SHEET_IMAGE 1번 · PAGE_IMAGE 9번(gpt-image-2).

**자주 헷갈리는 것**

- 화 전체 검수는 4.1 이 아니라 **gpt-5.1** 이다. 4.1 을 쓰는 검수는 이야기 검수 · 장 검수 · 표지 검수다.
- 캐릭터 시트는 **이야기와 나란히** 그리지만, 시트 사양(글)은 gpt-5.1 이 아니라 **gpt-4.1** 이다.
- 명령줄로 직접 돌린 작품(`run.py --no-story-review`)에는 이야기 검수 기록이 없다. 서버로 만든 작품은
  `NH_STORY_REVIEW` 기본 켜짐이라 늘 돈다.

## 길마다 다른 점

| | 바로 만들기 | 확인하고 만들기 | 내 내용으로(own) |
|---|---|---|---|
| 이야기 | 후보 4개 → 이야기 검수를 통과한 후보 중에서 AI 가 고름(`autoPick`) | 후보 4개를 사람이 고름(다시 짓기 가능) | 사람이 적은 내용으로 한 편을 짓고(STORY) 사람이 확인 · 고침 |
| 인물 | 멈추지 않음(기본 답으로 넘어감) | 상대 고르기 · 인물 확인에서 멈춤 | 인물 카드 확인 · 고침 |
| 캐릭터 시트 | 이야기와 나란히 그리고 그대로 감 | 시트를 보고 확정하거나 다시 그림 | 이야기 확인 화면에 같이 나옴 |
| 장면 | 멈추지 않음 | 장면 확인에서 멈추고 고칠 수 있음 | 장면 확인에서 멈추고 고칠 수 있음 |

멈추는 자리는 시간이 지나도 저절로 넘어가지 않는다. 사람이 답할 차례가 되면 푸시와 메일로 알린다.

## 검수 세 가지 — 무엇을 보고 언제 다시 그리나

| 검수 | 모델 | 무엇을 보나 | 걸리면 |
|---|---|---|---|
| 이야기 검수 `STORY_REVIEW` | gpt-4.1 | 후보마다 그림으로 옮겼을 때 어디서 막히는가 | **아무것도 막지 않는다.** 판정이 고르는 화면에 붙고, 바로 만들기는 통과한 후보 중에서 고른다 |
| 장 검수 `PAGE_REVIEW` | gpt-4.1 | 그 장만 보고 독자가 이해하는가(최우선) · 말풍선 화자 · 대사 · 앞 장과 이어지는가 · 연출 · 나레이션이 끝까지 맺어졌는가. 나레이션 첫 줄이 앞 장으로 되돌아가는지는 검수가 적은 값으로 코드가 판정 | `critical` 이면 그 장을 지우고 지적을 붙여 다시 그림 — 장마다 **1번까지**(`NH_PAGE_REVIEW_RETRY`) |
| 표지 검수 `COVER_REVIEW` | gpt-4.1 | 칸 하나 · 글상자 없음 · 제목 그대로 | 다시 그림 |
| 화 전체 검수 `FULL_REVIEW` | gpt-5.1 | 장 하나로는 안 보이는 것 — 같은 자세 반복, 앞뒤 모순, 흐름 | `critical` 이고 다시 그려 고쳐지는 것만 그 장을 다시 그림 — 장마다 **2번까지**, 전체 **3바퀴까지**(`JobRunner.MAX_PAGE_REDRAWS` · `MAX_FULL_REVIEW_ROUNDS`). 못 고쳐도 만들기는 성공으로 간다 |

**검수가 아직 안 보는 것**

- 나레이션이 어색한지(멋 부린 문장, 그림을 그대로 반복하는 설명). 나레이션 글은 장면 나누기에서 정해져
  장을 다시 그려도 안 바뀌므로, 잡으려면 장면 나누기 뒤에 검사를 둬야 한다(#628 「따로 볼 것」).
- 말풍선이 하나도 없는 장 — #629 에서 장면 글이 정하지 않은 침묵이면 다시 그리게 고치는 중.

## 안전 기준에 걸렸을 때

그림 단계(`SHEET_IMAGE` · `PAGE_IMAGE` · 캐릭터 카드)가 OpenAI 이미지 안전 기준에 걸리면 걸린 분류를 피해
스스로 1번 더 그린다. 또 걸렸을 때 사용자에게 무엇이 보이는지는 [safety.md](safety.md) 의 「걸렸을 때」.

## 그림 품질

만들기 화면의 세 가지가 `gpt-image-2` 의 `quality` 로 간다(`WebtoonQuality`). 편집실 다시 그리기도 그 작품의
품질 그대로 그린다.

| 화면 | quality | 한 장(실측) |
|---|---|---|
| 물결 | low | 약 77원 · 20초 |
| 파도(기본) | medium | 약 128원 · 37초 |
| 너울 | high | 약 301원 · 96초 |

한 편 전체 OpenAI 값은 파도 기준 약 $1.2(약 1,650원)였다(2026-10-04, 로컬 12편 · dev 4편 평균).

## 동시에 몇 개를 돌리나

- `lore.webtoon.workers`: 만들기 작업을 몇 편 나란히(줄 · 이야기 · 시트 확정 · 장면 · 화 전체 검수)
- `lore.webtoon.page-workers`: 장 그림을 서버 전체에서 몇 장 동시에 — 처리량은 사실상 이 값이 정한다
- 코드 기본값은 workers 2 · page-workers 3. 운영은 Parameter Store 에 workers 3 · page-workers 4 를 넣어 두었다
  (2026-10-04, 다음 운영 배포부터). 생성 부하 시험에서 처리량은 page-workers 가 정했고, 장 하나에 파이썬
  프로세스가 하나 떠서(약 150~200MB) 운영 메모리가 상한을 정한다

## 모델을 바꾸려면

하네스 `.env`(또는 서버 환경변수)에 `<단계>_MODEL` · `<단계>_PROVIDER` 를 적는다. 우선순위는
`<단계>_MODEL > NH_MODEL`(그림 단계는 `NH_IMAGE_MODEL`). 지금 무엇으로 도는지와 어느 줄이 이겼는지는:

```
cd webtoon/ai/new_harness && python3 run.py --plan
```

서버는 하네스를 띄울 때 자기 환경변수를 그대로 물려준다 — 운영은 Parameter Store `/lore/prod/<이름>` 에 넣으면
다음 배포 때 들어간다(이름은 소문자 · 밑줄, 환경변수로는 대문자). dev 는 박스 `.env` 와 `docker-compose.yml` 의
`environment:` 둘 다 필요하다([server.md](server.md)).
