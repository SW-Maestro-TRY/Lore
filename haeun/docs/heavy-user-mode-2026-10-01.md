# 「내 이야기로 만들기」 — 헤비 사용자 모드 설계

작성 2026-10-01 (#548). 설계 단계이고 코드는 없습니다. 지인 피드백(「돈 내고서라도
쓰고 싶은데, 통제할 수 있는 부분이 적어서 답답하다」)에서 출발했습니다. 처음에는
로어북(개인 설정집)을 답으로 잡았다가, 이 사용자가 정말 원하는 것은 **자기 이야기가
바뀌지 않고 자기가 그린 장면대로 웹툰이 되는 것**이라는 데까지 정리했습니다.
설정집 설계는 [personal-lorebook-design.md](personal-lorebook-design.md) 에 따로 있습니다.

## 1. 결론부터 (2026-10-01 확정)

축이 둘입니다. 첫 화면에서 **「만들고 싶은 내용이 있나요?」** 를 묻고, 없다고 한 사람에게만
**「중간에 확인할까요?」** 를 묻습니다. 화면 흐름과 문구는
[heavy-user-ux-2026-10-01.md](heavy-user-ux-2026-10-01.md) 에 있습니다.

| | 아이디어부터 — 바로 만들기 | 아이디어부터 — 확인하고 만들기 | 만들고 싶은 내용이 있어요 |
| --- | --- | --- | --- |
| 이야기 | AI 후보 4개, 서버가 고름 | AI 후보 4개, 사용자가 고름 | 사용자가 적음. 후보 없음 |
| 멈추는 자리 | 없음 | 이야기 고르기 · 시트 · **장면 확인** | **장면 확인** · 시트 |
| 자동 진행 | — | **없음** (지금의 5분이 없어짐) | 없음 |
| 코드 | 안 바뀜 | 장면 확인 추가, 타이머 제거 | 새 파이프라인 |

- 「헤비/라이트」「검수」를 화면에 쓰지 않습니다. 사용자는 자기 상황만 고릅니다.
- 장면 확인 화면은 세 길이 **같은 화면**을 씁니다. 「이대로 웹툰 만들기」가 가장 크고,
  고치지 않아도 됩니다. 시간이 아니라 사용자의 행동으로 진행합니다. 나가면 마이페이지
  「만드는 중」에서 이어서 합니다.
- 헤비 사용자는 AI가 더 많이 만들어 주길 원하는 사람이 아니라, **AI가 만든 것을 자기가
  원하는 만큼 통제하고 싶은 사람**입니다. 먼저 줘야 하는 것은 기능이 아니라 **멈출 수 있는
  지점**입니다.

헤비 모드의 중심은 로어북이 아니라 **장면 확인·수정**입니다. 로어북은 「내 세계는 이렇게
생겼다」, 내용 입력은 「내 이야기는 이것이다」, 장면 확인은 「이번 장면은 이렇게 보여 달라」
입니다. 셋이 경쟁하지 않고 층이 다릅니다.

## 2. 지금 파이프라인에서 AI가 혼자 정하는 것 (실측)

지금 흐름은 `이야기 → 장면 나누기(scene_prompt) → 장 그림(detail_image_prompt)` 입니다.
장면 나누기는 이미 별도 호출(`run.py --scenes`, `JobRunner:811`)이고 결과가
`scenes.json` 으로 남지만, **사용자에게 보여 주지 않고 바로 그림으로 갑니다.**

### 장면 단계에서 이미 글로 정해지는 것 — 보여 주기만 하면 됨

`scene_prompt` 출력 그대로입니다(장면마다).

| 칸 | 내용 |
| --- | --- |
| 직전 상태 | 앞 장이 끝난 자리 |
| 장소와 상황 | 어디서, 어떤 상황에서 |
| 벌어지는 일 | 이 장면의 사건 |
| 인물의 행동과 표정 | 누가 무엇을 하고 어떤 표정인지 |
| 겉모습·소지품·동행 | 시트와 달라진 것(젖은 머리, 든 물건) |
| 끝나는 상태 | 다음 장이 이어받을 자리 |
| 나레이션 | 쓸 수 있는 글(넣을지는 그림이 고름) |
| 등장인물 | 이름 — 외모 (화 내내 고정) |
| 이 화의 고정 설정 | 장소 이름·조직 같은 것 |

### 그림 모델이 혼자 정하는 것 — 지금은 사용자가 손댈 수 없음

`detail_image_prompt` 와 `detailart.build_continue_prompt` 가 「네가 정한다」로 넘기는 것입니다.

| 무엇 | 지금 어떻게 정해지나 | 근거 |
| --- | --- | --- |
| **컷 수** | 3~4개 안에서 그림 모델이 정함 | `detail_image_prompt:27` |
| **컷마다 어느 순간을 자르나** | 「여기서부터 ~ 여기서 끝낸다」 사이를 그림 모델이 나눔 | `build_continue_prompt` 「그 사이를 컷 몇 개로 어떻게 보여줄지 … 네가 정한다」 |
| **컷 크기·폭·좌우 치우침·여백** | 규칙(폭 다르게, 좌우 여백, 납작한 컷 1개 이하)만 있고 배치는 그림 모델 | `:28-39` |
| **카메라** — 샷 크기(클로즈업·전신·투샷), 앵글(로우·하이), 시선 | 「행동·감정이 더 잘 전달되도록」만 있고 선택은 그림 모델 | `:56` |
| **인물 위치·배치** (마주 보나, 뒤돌아 있나, 누가 앞인가) | 장면 글에 없으면 그림 모델 | — |
| **대사** — 누가 무슨 말을 하나 | **전부 그림 모델** | 「무슨 대사를 넣을지는 네가 정한다」 |
| **나레이션 중 무엇을 넣고 뺄지** | 글 모델이 준 후보 중 그림 모델이 고름 | `:52`, `narration_of` |
| **효과음** | 그림 모델 | `:60` |
| **배경의 구체적 모습** | 장소 이름만 있고 나머지는 그림 모델 | — |

피드백의 「답답하다」는 정확히 이 표의 아래쪽입니다. 사용자는 장면의 **내용**은 줬지만
**어떻게 보여 줄지**는 전부 AI에게 맡긴 상태입니다. 「왜 둘이 마주 보고 있지, 뒤돌아
있어야 하는데」가 그림이 나온 뒤에야 보입니다.

한 가지 주의: 대사를 글 모델(장면 단계)에 다 정하게 해 본 적이 있는데 대사가 설명조가
되고 남은 상자가 격언으로 채워졌습니다(2026-09-30). 그래서 지금은 대사를 그림 모델에
둡니다. **사용자가 직접 적은 대사는 다른 문제**입니다. 사용자 것은 그대로 씁니다.

## 3. 장면 설계 — 장면 초안을 보여 주고 자유롭게 고치게 (2026-10-01 결정)

**단위는 하나입니다. 장면 1개 = 웹툰 한 장 = 컷 3~4개.** 지금 코드가 이미 그렇습니다
(`scenes.json` 의 장면 하나가 `pages/pageNN.png` 하나). 사용자에게도 「장면 = 한 장」으로
보여 주고, 컷은 그 장 안에서 그림이 나누는 것으로 둡니다. 컷을 사용자 단위로 올리지
않습니다 — 컷마다 그림을 따로 만들면 그림 비용이 3~4배가 됩니다.

**컷 연출·대사를 미리 만들지 않습니다.** 사용자가 장면 글을 고치다 보면 「민준은 뒤돌아
있고, 서연이 뒤에서 나타나 '같이 쓰자'고 한다」처럼 연출과 대사를 알아서 적게 됩니다.
그래서 연출 칸을 따로 두지 않고, **장면 카드 하나를 자유 글로** 둡니다.

```
장면 3 / 7                                              [다시 나누기 + 메모]

┌──────────────────────────────────────────────────────────────┐
│ 비 오는 오후, 학교 정문. 민준이 비를 맞으며 서 있고, 서연이 뒤에서   │
│ 나타나 우산을 씌운다. 민준은 당황하고 서연은 무심한 척한다.       │
│ 서연: "같이 쓰자."                                              │
│ 둘이 우산 하나 아래 선 채로 끝난다.                               │
└──────────────────────────────────────────────────────────────┘
```

- 초안은 `scenes.json` 의 칸들(장소와 상황 · 벌어지는 일 · 행동과 표정 · 겉모습 · 끝나는
  상태 · 나레이션)을 **한 글로 합쳐** 보여 줍니다. 사용자는 그 글을 통째로 고칩니다.
- 고친 글은 그림 프롬프트의 「장면 내용」 자리에 그대로 들어갑니다. 사용자가 연출·대사를
  적었으면 그림이 따르고, 안 적었으면 지금처럼 그림 모델이 정합니다(「네가 정한다」 그대로).
  컷 대본 단계를 9월에 지운 이유(전부 적어 주면 안 적은 것까지 굳는다)가 여기서도 그대로
  지켜집니다 — 적힌 것만 지시입니다.
- 글이 바뀌면 「끝나는 상태」가 바뀔 수 있어 앞뒤 장이 안 맞을 수 있습니다. 첫 판에서는
  **다음 장의 「직전 상태」를 사용자가 고친 글의 마지막 줄로 바꿔 넣는** 것까지만 합니다.
- 장면 초안이 통째로 마음에 안 들면 「다시 나누기 + 메모」. 이야기 다시 만들기와 같습니다.
- 장면 합치기·나누기·순서 바꾸기는 첫 판에서 뺍니다.

**이 자리에서는 자동으로 넘어가지 않습니다.** 작업은 서버에 그대로 남아 있으므로 임시
저장은 따로 만들 것이 없고, 돌아오면 그 자리입니다. 마이페이지에 「고치는 중」 목록을
둡니다. 장면 초안을 읽기 전용 링크로 공유하는 것은 첫 판 다음입니다.

## 4. 「내 이야기로 만들기」 흐름 — 파이프라인을 다시 짭니다

```
① 내 캐릭터        지금 위자드 그대로(사진·설명·항목)
② 내 이야기        지금 「어떤 이야기를 볼까요」 칸. 길이 제한을 풀고 크게. (내 설정은 3단계 뒤)
③ AI 장면 초안      내 이야기 → 바로 장면 나누기. 이야기 후보 4개 · 이야기 검수 · 이야기 고르기가 다 빠집니다
④ 장면 고치기       3절. 무기한 멈춤
⑤ 시트 → 장 그림   지금과 같음
⑥ 장 다시 그리기    지금 편집실 메모
```

③이 지금과 가장 다른 곳입니다. 지금은 줄거리를 적어도 후보 4개를 만들고
(`story_prompt_seeded`) 고르게 하는데, 내 이야기는 고를 것이 아닙니다. 장면 나누기
(`scene_prompt`)가 이야기 본문 대신 **사용자가 적은 이야기**를 받아 바로 장면으로 나눕니다.
하네스 안에서는 `directions.json` 에 후보 하나(적은 이야기 그대로)를 넣고 바로 `--scenes`
로 가면 뒤 단계가 안 바뀝니다.

**크레딧**: 기본 생성은 지금과 같습니다. 컷마다 그림을 따로 만드는 「컷별 생성」은 그림이
3~4배라 나중에 유료 옵션으로만 둡니다. 첫 판에는 없습니다.

## 5. 진입 화면

지금 온보딩 첫 화면에 카드 둘을 둡니다. 기준은 하나입니다.

```
지금 만들고 싶은 이야기가 있나요?

┌ 아직 없어요 ─────────────────┐  ┌ 네, 있어요 ───────────────────┐
│ 캐릭터만 정하면 LORE 가        │  │ 내 설정과 이야기를 바탕으로     │
│ 어울리는 이야기를 만들어 드려요 │  │ 장면까지 확인하고 고치면서      │
│                               │  │ 만들어요                       │
│ [ 빠르게 만들기 ]              │  │ [ 내 이야기로 만들기 ]          │
└───────────────────────────────┘  └────────────────────────────────┘
```

「디테일」「라이트」「고급」은 쓰지 않습니다. 처음이면 왼쪽을 권하는 한 줄만 둡니다.

## 6. 첫 판에 만드는 것 — 셋

1. **장면 확인 자리** — `awaiting_scenes`. 장면 초안을 자유 글로 보여 주고 고치게. 자동 진행
   없음. #534 의 `awaiting_cast` 와 같은 골격(상태 · API · 화면 · 진행 시간). 「확인하고
   만들기」에도 붙고, 그쪽의 5분 타이머를 없앱니다.
2. **「만들고 싶은 내용이 있어요」 길** — 후보·고르기 없이 적은 내용을 바로 장면으로.
3. **첫 화면 둘로 나누기** — ux 문서 3-1.

설정집(로어북)은 그 뒤입니다. 「바로 만들기」는 건드리지 않습니다.

## 7. 비용·시간

- 장면 확인 자리 자체는 호출이 늘지 않습니다. 장면 나누기는 이미 하고 있습니다.
- 사람이 고치면 **장면 다시 나누기 없이** 고친 값을 그대로 그림에 넘깁니다. 글 호출 0회.
- 기다리는 자리가 하나 늘어서 진행 시간 계산(`JobEta`)에 대기 하나가 더 들어갑니다.
  「빠르게 결과부터」에서는 멈추지 않고 지나갑니다.

## 8. 위험

- **연출 칸을 채우면 그림이 나빠질 수 있습니다.** 그림 모델이 규칙(컷 폭 다르게, 여백)과
  사용자 지시 사이에서 흔들립니다. 첫 판에서는 연출 칸을 자유 글 하나로 두고, 무엇을 적을
  때 잘 되는지 실측한 뒤 칸을 나눕니다.
- **장면 나누기 자체가 마음에 안 들 때.** 「장면 다시 나누기 + 메모」를 둡니다. 이야기
  다시 만들기와 같은 방식입니다.
- **첫 판에서 장면 합치기·나누기를 못 하는 것**은 아쉽지만, 대신 「벌어지는 일」을 고쳐
  장면의 범위를 옮길 수 있습니다.

## 9. 성공 기준

- 장면 확인 자리에서 **한 장면이라도 고친 작품**의 비율. 고친 사람이 헤비 사용자입니다.
- 고친 작품의 장 다시 그리기 횟수가 안 고친 작품보다 줄어드는가.
- 완성 직후 설문의 「내가 생각한 이야기 맞다」.
- 피드백을 준 사람이 1을 보고 「이거면 돈 낸다」고 하는가.

## 10. 결정한 것 (2026-10-01)

1. 장면 고치기 자리를 먼저 만든다. 설정집은 그 뒤. — 동의
2. 연출 칸을 따로 두지 않는다. 장면 카드는 자유 글 하나. 컷 초안 자동 생성 없음.
3. 내 이야기 모드는 후보 1개가 아니라 **후보·검수·고르기 단계 자체를 뺀다.** 파이프라인을 다시 짠다.
4. 장면 확인 자리는 「확인하고 만들기」와 「만들고 싶은 내용이 있어요」에. 「바로 만들기」는 지금 그대로.
5. 내 이야기 모드에서는 **무기한 기다린다.** 서버에 남으니 임시 저장은 따로 없고, 공유(읽기 전용 링크)는 첫 판 다음.
6. 크레딧: 기본 생성은 지금대로. 컷별 생성은 나중에 유료 옵션.

7. 시간으로 진행을 정하지 않는다. 「그대로 만들기 / 수정하기」를 누를 때까지 기다린다.

## 11. 첫 실제 실행에서 나온 것 (2026-10-01, 아직 안 고침)

- **장면 하나만 고쳐서 다시 나누기.** 지금은 장면 글을 직접 고치는 것뿐이다. 「이 장면은
  이렇게 바꿔 줘」라고 적으면 AI가 **그 장면 하나만** 다시 짜 주는 길이 필요하다. 「장면
  다시 나누기」는 전체를 다시 하는 것이라 다르다.
- **왼쪽 걸음 「3 장면 나누기」가 눌리지 않는다.** 장면 초안을 만드는 동안(아직
  `awaiting_scenes` 가 아닐 때)과 그 뒤 상태에서 걸음 3을 눌러 볼 수 없다. `canView` 조건을
  손봐야 한다.
