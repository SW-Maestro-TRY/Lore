## P1

### 1. 재현성 — "같은 프롬프트, 같은 모델인데도 그림체가 다르게 나옴"

이미지 모델은 시드를 안 주면 매번 다른 난수로 출발한다. 시드 자체가 코드베이스
어디에도 없었다.

- `providers/gemini.py` — `_generation_config()` 가 `options.seed` 를 받으면
  `generationConfig.seed` 로 싣는다. 값이 없으면 키 자체가 안 붙는다.
- `run.py` — `job_seed(cfg, job)` 신설. `provider.options.seed_base` 를 뿌리로
  `sha1(condition|stem|cut_number|candidate)` 를 섞어 **컷마다 다른, 그러나 매번
  같은** 시드를 만든다. `run_job` 이 컷별 provider 를 만들 때 실어 보낸다.
  - 한 화 전체에 같은 시드를 박지 **않는다** — 그러면 컷들이 서로 닮아버려서
    아래 P2-1(배경 반복) 을 오히려 키운다.
  - 후보(c1·c2)도 시드가 갈린다. 안 그러면 후보를 여러 장 뽑아도 다 같은 그림이라
    고를 것이 없다.
  - `hash()` 를 안 쓴 이유: 파이썬 실행마다 값이 바뀌어서(PYTHONHASHSEED) 재현이
    목적인데 재현이 안 된다.
- `config.yaml` — `provider.options.seed_base` 를 **주석 처리된 채로** 넣었다.

### 2. 나이대 반영 — "18세인데 얼굴이 성숙해 보인다"

원인은 **나이가 프롬프트에 아예 안 들어가고 있었던 것**이다. `p1.json` 에 age
칸 자체가 없었고, `charsheet.Sheet` 에도 없었다. 세 군데를 이어 붙였다:

- `story-harness/prompts/p1.txt` — 출력 스키마에 `"age"` 신설 (**숫자만**).
  설명 문단에 "고등학생·청년 같은 말은 안 된다, 그림 하네스가 이 숫자를 읽는다"
  를 적었다.
- `webtoon-harness/charsheet.py` — `Sheet.age` 필드, `load()` 에서 읽기,
  `age_look(age)` (나이 → 얼굴 지시문), `age_warning(sheet)` (숫자를 못 뽑았을
  때만 알림), 그리고 `lock_text()` 가 `design_details` **앞**에 그 줄을 싣는다.
  - 숫자만 주면 모델이 거의 안 듣는다. **얼굴의 어디가 달라지는지**(볼살·턱선·
    눈 크기 비율)를 적어야 실제로 바뀐다. 6개 구간으로 나눴다.
  - 등신은 여기서 안 건드린다 — 그건 아래 P1-3 의 일이다.
- `run.py` — 나이를 읽었는지 / 못 읽었는지 / 아예 없는지를 각각 다르게 찍는다.

### 3. SD / MD / LD — 용어 충돌부터 풀어야 했다

**코드베이스에 이미 "sd" 가 있었다.** `render_style: normal|sd|emphasis` 의 sd 는
"코미디용 2~3등신 삽입 컷"이고, `config.yaml` 의 `styles.<이름>.sd` 가 그
프롬프트다. 사용자가 말하는 SD(등신 비율)와 **다른 것**이다. 이 충돌이 혼선의
근원이었다.

- `scenegen.py` — `HEAD_RATIO` 표(sd 2~3 / md 4~5 / ld 7~8등신) + `head_ratio()`
  + `head_ratio_tail()`. `assemble()` 이 `global_suffix` **뒤**에 붙인다.
- 키 이름을 `head_ratio` 로 따로 뒀다. 값은 sd/md/ld 그대로 쓴다 — 사용자가 그
  낱말로 말하기 때문이고, 키가 다르니 `render_style: sd` 와 헷갈릴 자리가 없다.
- **styles 의 PROPORTION 줄은 안 고쳤다.** 일곱 그림체가 전부 성인 등신(7~9)을
  박아 두었는데, 그걸 고치면 그림체마다 균형을 다시 잡아야 하고 예전 run 결과도
  바뀐다. 대신 뒤에서 덮어쓴다 — 이 저장소 규칙대로 뒤에 온 것이 이긴다.
- `landing/web` — 등신 비율 라디오 4개(기본/SD/MD/LD) 신설, `head_ratio` 로 제출.

### 4. 편지지 글자가 안 읽힘

화면(`screen_text`)은 이미 "비워 그리고 코드가 합성"하는데, **종이는 그 길이
없었다.** 한글 자모는 획이 많아 작은 크기에서 반드시 깨진다.

- `scenegen.py` — `PROP_TEXT_CLAUSE` + `prop_text_clause(cut, panel_text)`.
  서술에 letter/note/sign/book 류 낱말이 보이면 "읽히는 척하지 마라 — 글자
  모양의 질감으로 남기거나 비워라, 낱말·이름·서명을 지어내지 마라"를 붙인다.
  `screen_text` 가 있는 컷에는 안 붙인다(그쪽이 더 정확한 지시라 겹치면 어긋난다).
- 편지 속 이름이 틀렸던 문제는 P0-3(`prop_text_name_check`)에서 이미 처리됐다.

### 5·6·7. 톤 전환 빌드업 · 대사 구어체 · 컷 앵글 연속성

`story-harness` 쪽. 자세한 것은 커밋과 `test_gates.py` 참고.

- **톤 빌드업** — `webtoon.py:tone_warnings()` 에 검사 추가: 급전환 문장이 있는데
  **앞 두 컷**에 `beat` 가 `build`/`turn` 이 아니면 경고. advisory.
  `prompts/w7.txt` 에 "톤 전환에는 최소 1비트 빌드업" 규칙(✗/○ 예시).
- **대사 구어체** — 프롬프트 전용. `w7.txt` 에 말맛 규칙 신설. 피드백에서 나온
  실제 쌍을 그대로 넣었다("저 소리는 누구지?"→"뭐지?", "미세한" 어색함,
  "~일까, ~일지도" 자기서술 헤지 금지, 소리 내어 읽어 보는 검사).
  - `prose_warnings` 에 정규식은 **일부러 안 넣었다** — "저 소리는 누구지?"가
    맞는 맥락도 있어서 오탐이 난다.
- **앵글 연속성** — `webtoon.py:facing_warnings(cuts)` 신설(advisory). 붙어 있는
  두 컷이 정면↔뒷모습으로 튀면 반측면 완충을 권한다. `w7.txt` 에도 같은 규칙.
  - 스키마는 안 건드렸다. `angle` enum 은 카메라 높이(수평/부감/앙각/…)라
    앞뒤 방향 칸이 아예 없고, 칸을 새로 만들면 예전 run 이 깨진다. 그래서
    `description` 텍스트 검사로 갔다.

## P2

### 1. 컷별 배경 변주 — "1컷·2컷 배경이 완전히 동일"

`run.py:cond_extra()` 의 존 문구는 이미 "카메라를 바꿔라"라고 말하고 있었지만
**얼마나** 바꿔야 하는지를 안 말해서 모델이 몇 도만 틀고 같은 그림을 냈다.
붙어 있는 두 패널에 대해서만 최소치를 못박았다 — 샷 거리를 한 단계 이상
바꾸거나, 장소의 다른 부분으로 옮기거나. "같은 그림을 더 타이트하게 자르는 것은
변화가 아니다"를 명시. 화면 전체에 걸면 장소가 흔들려서 존을 고정한 이유가
사라지므로 인접 패널로만 제한했다.

### 2. 스티커 평면화 — "3D 느낌이라 그림체와 안 맞는다"

`scenegen.STICKER_FLAT` + `sticker_flat(cfg)` (`config.flat_stickers`).
땀방울·하트·별·물음표·뭉게구름을 "같은 손이 같은 잉크로, 같은 선 굵기로 그린
평면"으로 못박고 그라데이션·광택·드롭섀도·베벨·글로우를 전부 금지한다.
`landing` 은 항상 켠다 — 사용자가 끄고 싶어할 이유가 없는 값이다.

### 3. 포즈 — "'이 검 엄청 가벼워요' 컷의 포즈가 어색하다"

포즈는 코드가 한 마디도 안 하던 자리였다(거리·구도·시선은 절이 있는데 몸은
없었다). `scenegen.POSE_CLAUSE` + `pose_clause(cfg, cut)`
(`config.pose_guidance`). 무게중심·어깨와 골반의 기울기·팔의 목적을 요구하고,
드는 물건의 무게가 손목 각도와 팔의 힘에 드러나야 한다고 적었다. 정면으로
뻣뻣하게 선 "캐릭터 선택 화면" 자세를 금지. **인서트(사물) 컷에는 안 붙인다** —
사람 없는 컷에 포즈 지시를 하면 없는 인물을 만들어 넣는다.

### 4. 조명 톤이 소재만으로 어두워짐

로판을 골랐는데 "덫에 걸린 생쥐" 장면이 피 묻은 덫과 새빨간 조명으로 나왔다.
**장르가 이 파이프라인에 한 번도 전달된 적이 없었다** (`scenegen` 전체에 genre
가 없었다). `scenegen.genre_tone_guard(cfg)` 신설 — 장르가 스릴러·공포·오컬트
계열이 아니면 `treatment_text()` 끝에 톤 상한을 붙인다: 덫·밤 숲·다친 동물은
상황이지 공포 장면이 아니다, 핏빛/병색 조명과 유혈을 mood 가 직접 요구하지
않는 한 쓰지 마라, 밤 숲에는 차가운 달빛·푸른 그림자·안개·등불을 써라.
`landing` 이 사용자가 고른 장르를 `config.genre` 에 채운다.

### 5. 작화 사고 검수 — "생쥐 머리가 발로, 몸 위에 새싹"

프롬프트로는 못 막는다 — 모델은 자기가 잘못 그린 줄 모른다. 그린 다음에 보고
잡아야 한다. `vision.py` 에 이미 "그림을 모델에게 되묻는" 길이 있어서 그대로 썼다.

- `vision.INSPECT_ASK` + `inspect_art(img, ...)` — 손발 개수/구조, 사라지거나
  두 번 그려진 부위, 동물·사물 구조 오류, 몸 위에 자란 것, 공중에 뜬 물건,
  녹은 얼굴, 읽을 수 없는 글자를 찾는다. **찾지 않는 것**(그림체 취향, 밋밋한
  구도, 만화적 과장)도 같이 적었다. 확신 없으면 넣지 말라고 못박았다.
- `run.py --check-art` — 컷이 성공할 때마다 되물어 `art_issues.jsonl` 에 남긴다.
- **기본으로 안 돈다.** 컷당 호출이 하나씩 더 붙어 원가가 오른다(지금도 1회
  1,600원 vs 지불 의사 700~800원으로 역마진이다). 그리고 **판정이 아니라 제보**다
  — 자동 재생성하지 않는다. 오탐이 있고, 다시 뽑는 것도 돈이다.

### 6. 로딩 UX · 비주얼 아이덴티티

컬러 팔레트는 이미 `style.css` 의 `:root` 에 통일돼 있어서 마스코트만 만들었다.

- `landing/web` — 마스코트 **"먹이"** (먹 한 방울이 굳어 생긴 것이라는 설정).
  인라인 SVG 라 외부 파일이 없고, 색은 `--accent`/`--gold` 만 쓴다.
  단계별로 표정과 소품이 바뀐다: 이야기=쓰는 얼굴 / 시트·그림=붓을 들고 칠함 /
  콘티·조립=읽는 얼굴 / 승인 대기=갸웃 / 완료=반짝 / 실패=회색으로 주저앉음.
  숨쉬기·눈깜빡임 애니메이션, `prefers-reduced-motion` 존중.
- 마스코트가 지금 무엇을 하는지 한 줄로 말한다(`#mascotLine`) — 아래 rail 의
  기계적인 로그와 역할이 안 겹치게 사람 말로.

## 추가 — 모델이 거절했을 때 (P0/P1/P2 밖, 작업 중 나온 요구)

> "나이가 막 13살 모델이고 그러면 이미지 생성해서 못 만들 수도 있긴 하거든?
>  이제 그런 오류들 있으면 그것들 다 기록하고 뭘로 오는지 보고 다 저장해놓고
>  확인하고 사용자한테도 보여주자"

거절(refusal)은 실패와 성격이 다르다 — 다시 시도해도 같은 답이 오고, 고칠 사람은
우리가 아니라 **입력을 쓴 사용자**다. 그런데 지금까지는 "생성 실패"로 뭉개져서
사용자가 손댈 곳을 알 수 없었다.

- `providers/base.py` — `ProviderError` 에 `refusal: bool`, `detail: dict` 추가.
- `providers/gemini.py` — 두 갈래를 다 잡는다:
  - 프롬프트 단계 차단(`candidates` 가 아예 없음) → `promptFeedback` 의
    `blockReason`·`blockReasonMessage`·`safetyRatings` 를 통째로 담는다.
  - 이미지 대신 글로 거절 → `finishReason` 이 `PROHIBITED_CONTENT`/`SAFETY`/
    `IMAGE_SAFETY`/`BLOCKLIST`/`SPII`/`RECITATION` 이면 refusal.
    **모델이 한 말을 안 자르고 그대로 담는다** — 무엇을 고쳐야 할지는 그 문장에만
    있다.
- `run.py` — `record_refusal()` 이 `refusals.jsonl` 에 **프롬프트 전문까지** 남기고,
  `REFUSAL_HINTS` 로 "무엇이 걸렸고 어디를 고치면 되는지"를 터미널에 찍는다.
  (`PROHIBITED_CONTENT` → "캐릭터 나이가 어리면 걸리는 경우가 많습니다" 등)
- `landing/pipeline.py` — 출력에서 거절 줄을 보면 `saw_refusal` 을 세우고,
  그때만 `refusals.jsonl` 을 읽어 스냅샷에 싣는다(매 폴링마다 파일을 읽지 않는다).
  같은 사유 표를 화면 말로 한 벌 더 갖는다.
- `landing/web` — 진행 화면에 거절 패널 신설. 실패(회색·재시도로 풀림)와 눈으로
  구분되게 테두리를 주고, 사유 코드 · 고칠 곳 · **모델이 한 말** · 해당 장면
  설명을 같이 보여준다. "다시 시도해도 같은 결과"라고 명시.

  없으면 `None`.
- 거절 경로: 프롬프트 단계·응답 단계 두 갈래를 가짜 응답으로 태워
  `refusals.jsonl` 기록과 `landing.read_refusals()` 읽기까지 확인.
- `build_config` : 기본/선택/따옴표 섞인 장르 세 경우 모두 YAML 이 안 깨지는 것 확인.

### 하지 않은 것

- **실제 API 를 태운 end-to-end 실행은 안 했다.** 비용이 들고 외부 호출이라
  사용자 승인 없이 진행하지 않았다. 특히 다음은 실제로 한 번 돌려서 봐야 한다:
  - 시드를 켰을 때 그림체 흔들림이 실제로 줄어드는가 (`seed_base` 는 아직
    주석 처리 상태다 — 켜서 A/B 를 봐야 한다)
  - `head_ratio: sd` 가 정말 2~3등신으로 나오는가 (styles 의 PROPORTION 을
    뒤에서 덮는 방식이 이기는지)
  - `--check-art` 의 오탐률이 쓸 만한 수준인가
  - 나이를 13 으로 넣었을 때 실제로 거절이 오는가, 오면 새 패널이 제대로 뜨는가
- **브라우저 눈 확인을 못 했다.** Chrome 확장이 이 세션에 연결돼 있지 않았다.
  마스코트·거절 패널·등신 라디오의 레이아웃은 정적 미리보기 HTML 로만 만들어
  두었고, 실제 화면 확인은 남아 있다.
