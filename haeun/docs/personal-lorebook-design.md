# 개인 설정집 설계 — 헤비 사용자가 프롬프트를 통제하게

작성 2026-10-01 (#548). 아직 설계 단계이고, 코드는 없습니다. 이 문서는 설정집(로어북) 쪽만 다룹니다. 헤비 사용자 모드 전체와 장면 설계는 [heavy-user-mode-2026-10-01.md](heavy-user-mode-2026-10-01.md) 를 먼저 보세요 — 결정 순서가 그쪽이 먼저입니다. 결정할 것은 맨 아래에 있습니다.

## 왜 만드나

지인이자 사용자에게 받은 피드백입니다.

> 이거 정말 굉장히 쓰고 싶은데, 돈 내고서라도 쓰고 싶은데, 프롬프트를 수정할 수
> 있으면 좋겠다. 내가 통제할 수 있는 부분이 적어서 답답하다. 개인화된 프롬프트가
> 필요하다. 제타의 로어북 같은.

지금 서비스는 「사진 한 장, 달칵」을 목표로 만들어져 있습니다. 그런데 자기 캐릭터를
그릴 정도로 애정이 있는 사람, 5,000원을 낼 사람은 라이트 사용자가 아닙니다. 이
사람들이 바라는 것은 「그림 그리기가 귀찮다」를 대신해 주는 것이지 「아무거나 빨리」가
아닙니다. 돈을 받으려면 이 사람들이 원하는 통제를 줘야 합니다.

## 지금 사용자가 통제할 수 있는 것

실제 코드 기준입니다(`run.py` `input_block` · `JobService.CreateRequest` · 진행 화면).

| 언제 | 무엇 |
| --- | --- |
| 만들기 시작 | 이름 · 사진(과 사진 메모) · 설명 · 항목 8개(나이·성별·직업·성격·말투·과거·관계·약점) · 장르 · 그림체 · 줄거리(「어떤 이야기를 볼까요」) · 캐릭터 카드 |
| 만드는 중 | 이야기 후보 다시 만들기 메모 · 고른 이야기 본문 직접 고치기 · 시트 다시 만들기 메모 · (현대 로맨스) 상대 인물 고르기(#534) |
| 완성 뒤 | 편집실에서 장 다시 그리기 메모 |

못 하는 것:

- 세계관·인물 설정을 **작품 사이에 다시 쓰기.** 매번 처음부터 적어야 합니다.
- 이야기 규칙 고정. 톤, 시점, 하지 말 것, 꼭 넣을 것 같은 것을 정해 둘 자리가 없습니다.
- 어느 단계에 내가 적은 것이 어떻게 들어갔는지 보기.
- 같은 설정으로 다음 화.

서비스 쪽에는 이미 로어북이 있습니다(`new_harness/lorebook.json`, #502). 세계 14개마다
「그 세계에서만 일어나는 사건의 출발점」을 재료로 두고, 이야기 단계는 후보마다 배정하고,
장면·그림 단계는 글에 키워드가 나오면 붙입니다. **이 구조를 사용자 것으로 열어 주는
것이 이 설계의 뼈대입니다.** 키워드로 켜지는 항목이라는 점에서 제타·SillyTavern
로어북과 같은 모양이고, 사용자가 이미 아는 방식입니다.

## 무엇을 만드나 — 「설정집」

사용자가 만들어 두고 작품마다 골라 쓰는 것입니다. 항목의 묶음이고, 항목은 네 종류입니다.

| 종류 | 무엇을 적나 | 어디에 들어가나 | 켜지는 때 |
| --- | --- | --- | --- |
| **세계** | 제도·장소·물건·관행. 서비스 로어북 재료와 같은 형식 | 이야기 · 장면 · 그림 | 항상, 또는 키워드가 글에 나올 때 |
| **인물** | 이름 · 생김새 · 성격 · 말투 · 주인공과의 관계. #534 인물 단계와 같은 칸 | 인물 · 이야기 · 장면 · 그림(생김새만) | 항상, 또는 이름이 나올 때 |
| **규칙** | 이야기 규칙. 톤, 시점, 하지 말 것, 꼭 넣을 것, 대사 말투 | 이야기 · 장면 | 항상 |
| **그림** | 그림에서 지킬 것. 옷차림 고정, 배경, 하지 말 것 | 그림 | 항상 |

항목마다 있는 칸: 제목 · 본문 · 켜지는 조건(항상 / 키워드 목록) · 쓰이는 단계 · 순서 ·
켜짐/꺼짐.

거기에 **작가 메모** 하나가 더 있습니다. 작품 하나에만 붙는 자유 글입니다. 지금 다시
만들기 때만 받는 메모(`--note`)를 **만들기 시작 때부터 받아서 모든 단계에 붙이는**
것입니다. 저장하면 규칙 항목이 됩니다.

## 어디에 어떻게 들어가나

단계별 프롬프트에서 사용자 입력이 붙는 자리 바로 뒤에 붙습니다.

| 단계 | 프롬프트 | 붙는 자리 | 무엇이 |
| --- | --- | --- | --- |
| 인물 | `cast_prompt` | 입력 블록 뒤 | 인물 항목(적은 인물로 취급 → 새로 만들지 않음, #534) · 규칙 |
| 이야기 | `story_prompt` · `story_prompt_seeded` | `story_input_block` 뒤, 서비스 세계 재료 앞 | 세계 · 인물 · 규칙 · 작가 메모 |
| 장면 | `scene_prompt` | `scene_input_block` 뒤 | 세계(키워드) · 인물 · 규칙 · 작가 메모 |
| 그림 | `detail_image_prompt` | `character_block` 뒤 | 인물 생김새 · 그림 항목 · 세계(키워드) |

우선순위는 **사용자 설정집 > 캐릭터 카드 > 서비스 세계 재료**입니다. 사용자가 적은
것은 「적힌 것」으로 취급합니다. 지금 프롬프트의 「설명에 없는 성격을 붙이지 않는다,
적힌 것을 바꾸지 않는다」 규칙이 설정집에도 그대로 걸립니다.

서비스 세계 재료는 사용자 설정집에 세계 항목이 있으면 **줄입니다**(후보당 2개 → 1개
또는 0개). 사용자가 자기 세계를 적었는데 서비스 재료가 판을 흔드는 일을 막으려는
것입니다. 오늘 서연화 실험에서 로어북 재료(상견례·짐 상자)가 네 후보를 덮는 것을
봤습니다.

키워드 스캔은 지금 `lorebook.scan` 을 그대로 씁니다. 사용자 항목만 세계 키 대신
설정집 번호로 격리합니다.

## 통제감의 핵심 — 무엇이 들어가는지 보여 준다

피드백의 「답답하다」는 기능이 없어서이기도 하지만, **무엇이 어떻게 들어갔는지 볼 수
없어서**이기도 합니다.

- **보내기 전 미리 보기.** 만들기를 누르기 전에 이야기 단계에 실제로 들어갈 사용자
  부분(입력 블록 + 켜진 설정집 항목 + 작가 메모)을 그대로 보여 줍니다. 여기서 바로
  고칠 수 있습니다.
- **만든 뒤 「이번에 들어간 것」.** 이야기 고르기 화면과 완성 화면에 이번 작품에 켜진
  설정집 항목 목록을 접어서 둡니다. run 폴더의 `story_prompt.txt` 에서 사용자 부분만
  잘라 보여 주면 됩니다.
- **시스템 프롬프트 원문은 보여 주지 않습니다.** 판정 기준·검수 규칙은 서비스의
  것이고, 그것까지 열면 품질과 안전을 책임질 수 없습니다. 대신 사용자 부분은 전부
  보여 주고 전부 고칠 수 있게 합니다.

## 다음 화의 씨앗 — 완성작에서 설정집으로

완성 화면에 「설정집으로 저장」을 둡니다. 이 작품에서 세워진 인물(인물 단계 결과,
`cast.json`)과 세계(고른 재료), 고른 이야기의 전제를 설정집 항목으로 넣습니다.
0921 멘토링에서 나온 「웹툰에서는 스토리가 정적 데이터(페르소나·메모리)를 바꾸는
트리거」가 이것입니다. 다음 화를 만들 때 이 설정집을 고르면 같은 인물과 세계로
이어집니다.

## 데이터

```
webtoon_lorebook        id · user_id · name · created_at · updated_at
webtoon_lorebook_entry  id · lorebook_id · kind(world|cast|rule|art) · title · body
                        · keys(text[]) · always(bool) · stages(text[]) · sort · enabled
webtoon_job             + lorebook_id (nullable) · + author_note (text)
```

- 작품을 만들 때 **설정집 사본을 `input_json` 에 같이 넣습니다.** 나중에 설정집을
  고쳐도 옛 작품이 무엇으로 만들어졌는지 남습니다.
- 하네스에는 `character.json` 의 `lorebook: {entries: [...]}` 와 `note` 로 넘깁니다.
  `run.py` 에 `userbook.py` 모듈을 두고 단계별 블록을 만듭니다. 자바가 부르는 파이썬은
  넷 그대로입니다.
- 항목 저장 때 입력 글 검사(`SafetyGuard`)를 거칩니다. 지금 설명·줄거리와 같은 검사입니다.
- 길이 상한: 항목 하나 2,000자, 항상 켜지는 항목 합계 8,000자. 넘으면 순서가 뒤인
  것부터 뺍니다. 프롬프트가 길어지면 지시를 덜 따르는 문제가 비용보다 먼저 옵니다
  (글 단계 전체 비용은 한 화에 약 250원이라 돈은 문제가 아닙니다).

## 화면

| 어디 | 무엇 |
| --- | --- |
| 마이페이지 → 설정집 | 설정집 목록. 항목 추가·수정·순서·켜기끄기. 종류별 칸 |
| 만들기 위자드 | 「설정집 쓰기」 고르기(없으면 그냥 진행) · 작가 메모 칸 · 보내기 전 미리 보기 |
| 이야기 고르기 | 「이번에 들어간 설정집 항목」 접힌 목록 · 「설정집 없이 다시 만들기」 |
| 완성 | 「설정집으로 저장」 |

## 단계 나누기

| 안 | 들어가는 것 | 드는 품 | 얻는 것 |
| --- | --- | --- | --- |
| **A** | 작가 메모(만들기 시작 때부터, 모든 단계) + 마이페이지에 규칙으로 저장·재사용 + 미리 보기 | 작음. 서버 칸 하나, 하네스 인자 하나, 화면 칸 둘 | 통제감이 바로 생김. 피드백 준 사람에게 바로 보여 줄 수 있음 |
| **B** | A + 세계·인물·그림 항목(항상 켜짐) + 우선순위(서비스 재료 줄이기) + 이번에 들어간 것 보기 | 중간. 표 둘, 마이페이지 화면, 하네스 모듈 | 「내 세계, 내 인물」이 작품마다 유지됨 |
| **C** | B + 키워드 트리거 + 단계 지정 + 완성작에서 설정집으로 저장 | 큼 | 제타 로어북과 같은 수준, 다음 화 연재의 기반 |

A → B → C 순서로 가되, **설계는 B를 목표로 잡고 A를 먼저 냅니다.** A는 지금 있는
`--note` 를 앞으로 당기는 것이라 하루 안에 됩니다.

## 위험과 대응

- **사용자 글이 서비스 규칙과 부딪힌다.** 예를 들어 「반전을 넣지 마라」를 적으면 지금
  「후보마다 반전 하나」 판정과 충돌합니다. 사용자 설정집이 이깁니다. 사용자가 적은
  것은 사용자 책임이고, 미리 보기에서 무엇을 적었는지 보이게 합니다.
- **품질이 나빠졌을 때.** 「설정집 없이 다시 만들기」 버튼으로 바로 비교할 수 있게
  합니다. 오늘 페르소나 있음·없음 비교와 같은 방식입니다.
- **긴 설정집.** 상한과 순서로 막습니다.
- **안전.** 항목 저장 때 검사합니다.
- **효과가 있는지 모른다.** 내기 전에 설정집 있음·없음을 같은 입력으로 비교합니다.
  오늘 페르소나를 이야기 단계에 넣었더니 판이 얌전해진 것처럼, 규칙이 이야기를
  좁힐 수 있습니다.

## 검증 — 무엇을 보면 잘된 것인가

- 헤비 사용자 정의: 자기 캐릭터로 2편 이상 만들고, 설정집 항목이 3개 이상인 사람.
- 볼 것: 설정집을 만든 사람 비율 · 설정집을 쓴 작품의 완주율 · 다시 만들기 횟수가
  줄어드는지 · 완성 직후 설문(`validation.md` S1~S6)의 「내 캐릭터 맞다」 답 ·
  유료 전환.
- 피드백을 준 사람에게 A 판을 먼저 보여 주고 다시 묻습니다.

## 하지 않는 것

- 시스템 프롬프트 원문 편집.
- 모델 고르기.
- 설정집 공유·공개. 나중에 생각합니다.

## 결정할 것

1. **첫 판 범위** — A만 먼저인지, B까지 한 번에인지.
2. **설정집 단위** — 사용자당 하나인지, 여러 개(작품 세계별)인지. 여러 개면 위자드에
   고르는 칸이 필요합니다.
3. **완성작 → 설정집 저장**을 첫 판에 넣을지. 넣으면 다음 화 연재와 바로 이어집니다.
4. **유료와 묶을지** — 설정집을 유료 기능으로 둘지, 크레딧과 별개로 둘지.
5. **미리 보기 범위** — 사용자 부분만인지, 서비스 세계 재료(어떤 재료가 배정됐는지)까지
   보여 줄지.
