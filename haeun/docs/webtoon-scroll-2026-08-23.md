# 세로 스크롤 연출 — 조사와 반영 (2026-08-23)

실사용자 지적: **"컷은 나오는데 웹툰이 아니라 만화 여덟 칸을 세로로 잘라 놓은 것

## 이미 되어 있던 것

조사 전에 코드를 먼저 읽었다. 세로 스크롤 연출의 뼈대는 대부분 이미 있었다.

- **컷 하나 = 이미지 한 장** (`webtoon-harness/strip.py`). 격자가 안 생기고,
  말풍선 자리를 코드가 알고, 컷 사이에 여백을 둘 수 있는 구조.
- **여백을 코드가 센다** (`story-harness/webtoon.py` `derive_layout`). 전환 유형과
  beat 에서 `gap_after` 0~3 을 배치하고, 낙차 자리가 없는 화는 스팅어 직전을 벌린다.
- **시선이 아래로 흐른다** (`gaze`). 마지막 컷에서만 독자를 본다.
- **통컷(bleed)·칸 밖으로(breakout)** — 세로 스크롤에서만 되는 칸 사용법이
  콘티 어휘에 있고 그림 프롬프트까지 내려간다.
- **뷰어의 낙차 여백이 80vh** — 화면 하나가 통째로 빈다.

그래서 문제는 "연출이 없다"가 아니라 **세 자리가 비어 있다**였다.

## 비어 있던 세 자리

### 1. 제품이 컷 모드를 안 쓰고 있었다 ← 사용자 체감의 1순위

`landing/pipeline.py` 의 `MODE = "scene"` 은 **한 이미지에 컷 3개를 묶어** 굽는다.
비용이 1/3 이라 그렇게 골랐고, 그 대가는 같은 파일에 이미 적혀 있었다 —
"모델에게 한 캔버스에 컷 3개를 배치하라고 하면 격자 말고 다른 답이 없다",
"컷 사이 여백을 모델이 정하게 된다". 위에 적은 여백 계산이 **제품 경로에서는
한 번도 쓰이지 않고 있었다.**

→ 폼에 **연출** 선택을 추가했다. `빠르게`(한 장에 3컷, 기본 — 지금까지의 방식) /
`웹툰`(컷마다 한 장). 기본값은 바꾸지 않았다 — 비용이 3배가 되는 선택은 사용자가
한다. 크레딧 표시도 선택을 따라간다. 다시 그리기(regen)는 이제 폼이 아니라
**떨어진 파일**을 보고 모드를 정한다(`run_mode`) — 서버를 껐다 켜도, 하네스를 직접
돌린 실행에서도 맞는다.

### 2. 붙인 컷의 배경이 이어지지 않았다

여백을 잘 배치해도 붙여 놓은 두 컷이 서로 무관한 그림이면 붙인 뜻이 없다. 오히려
`PREV_CUT_CLAUSE` 는 "직전 컷의 구도·프레이밍을 절대 베끼지 마라"고 못박고 있었다
(그림체만 이어지게 하려는 문구다).

→ 콘티가 **이어지는 자리를 계산**한다 (`vertical_link`). 앞 컷과 여백 0 으로 붙어
있고, zone 이 같고, 둘 다 데포르메가 아닌 자리다. 그림 단계에서는
`LINK_CUT_CLAUSE` 가 그 한 줄만 되돌린다 — 같은 장소를, 같은 빛으로, 같은 방향에서,
**조금 아래를** 본다. 무대는 그대로 두고 카메라만 내려가므로 스크롤 자체가 카메라가
된다. 콘티 프롬프트(`w7.txt`)에도 "붙는 컷은 같은 zone 에 두고 서술을 '같은 곳의
조금 아래'로 쓴다"를 명시했다.

기본은 꺼짐이다 (`config.yaml` 의 `vertical_link: false`). 제품에서 `웹툰` 을 고른
실행만 켠다. 직전 컷이 첨부되는 조건(S+·D)에서만 뜻이 있고, 첨부가 없으면 아무
문구도 안 붙는다 — 붙일 그림이 없는데 "아래를 보라"고만 하면 엉뚱한 곳이 나온다.

### 3. 여백의 절대 크기가 작았고, 뷰어와 PNG 가 서로 달랐다

`GAP_RATIO` 는 폭 대비 `0 / 0.07 / 0.26 / 0.62` 였다. 폭 800px 이면
**0 / 56 / 208 / 496px**. 작법이 쓰는 눈금은 동작 100–150 · 감정 200–300 ·
장면 전환 400–600 · 낙차 600–800px 이라, 양 끝이 어긋난다 — 1(56px)은 "붙인 것"과
눈으로 구분이 안 가고, 3(496px)은 낙차가 아니라 "조금 넓은 여백"이 된다.
게다가 뷰어는 3 을 이미 80vh 로 그리고 있어서, **같은 화를 뷰어로 볼 때와 PNG 로 볼
때 호흡이 달랐다.**

→ `config.yaml` 에 `scene.gap_ratio` 를 추가했다. 비워 두면(기본) 예전 값 그대로라
이미 뽑아 둔 화의 PNG 가 안 바뀐다. 제품의 `웹툰` 모드가
`{0: 0.0, 1: 0.16, 2: 0.32, 3: 0.90}` = **0 / 128 / 256 / 720px** 로 켠다.

⚠️ 남은 차이: 작법서의 픽셀 값은 화면이 짧던 시절 것이라, 19.5:9 폰에서 폭 800px
캔버스의 한 화면은 캔버스 좌표로 1,700px쯤이다. 720px 은 화면의 약 40% 다. 낙차를
화면 하나로 맞추려면 3 을 1.8 쯤으로 올려야 하고, 대신 화 전체가 눈에 띄게 길어진다.
지금은 작법서 값을 기본으로 두고 그 사실을 config 주석에 적어 뒀다.

## 확인 도구 — 스크롤 폴드 눈금

독자는 화 전체를 안 본다. 화면 하나를 보고 그 끝(폴드)에서 엄지가 멈춘다. 폴드 바로
아래가 리빌·임팩트면 계속 내려가고, 평평한 대사 컷이면 거기서 빠져나간다.

컷 뷰어에 **스크롤 폴드** 토글을 추가했다(기본 꺼짐). 켜면 화면 하나 높이마다 띠 위에
점선이 그어지고 "화면 2 · 화면 3 …" 이 붙는다. 창을 좁히면 눈금이 따라 움직이므로
폰에서 폴드가 어디 떨어지는지를 같은 창에서 볼 수 있다. 배경이 이어지는 컷에는
`↕ 이어짐` 표시가 붙는다.
