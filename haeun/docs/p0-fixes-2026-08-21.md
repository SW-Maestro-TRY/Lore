이어서 사용자가 "다른 장르들도 로판처럼 필수 트로프가 빠진 게 있는지 확인해서
고쳐줘 + 판타지/일상도 장르 목록에 추가해줘"를 요청해 같이 처리했다.

## P0-1. 캐릭터 시트 승인 없이 그대로 진행됨

**문제**: `landing/pipeline.py`가 `story.py --charsheet ... --yes`로 불러 기존
확인 게이트를 다 건너뛰고, 후보 1장이면 사람 개입 없이 자동 채택했다. 시트가
나온 뒤 사람이 보는 지점이 랜딩 파이프라인에 전혀 없었다.

**바뀐 것** (하네스는 그대로, `landing`만 수정):
- `landing/pipeline.py` — `Job.status`에 `"awaiting_sheet_approval"` 추가.
  `Job`에 `sheet_approval: threading.Event`, `sheet_decision: str`,
  `decide_sheet(decision)` 메서드 신설 (state.json에는 안 남는 런타임 전용 필드 —
  서버 재시작 시 `awaiting_sheet_approval`도 `"running"`과 같이 `error`로 강등).
  `execute()`의 2단계(캐릭터 시트)가 `while True:` 루프가 되어, 시트가 나올 때마다
  멈추고 `sheet_approval.wait()`; `decide_sheet("retry")`면 `charsheet/` 폴더를
  통째로 지우고(story.py의 "다시 뽑고 싶으면 이 폴더를 사람이 직접 지운다" 방식과
  동일) 루프를 한 번 더 돈다. `Job.cancel()`도 이 Event를 깨우도록 고쳐서, 승인
  대기 중에 "중단"을 눌러도 실제로 멈추게 했다.
- `landing/serve.py` — 새 엔드포인트:
  - `POST /api/jobs/<id>/sheet-decision` `{"decision":"approve"|"retry"}`
  - `GET /api/jobs/<id>/photo` (업로드한 원본 사진 — 기존 `/sheet` 엔드포인트와
    나란히 승인 화면에 씀)
- `landing/web/index.html` / `app.js` / `style.css` — `#sheetApproval` 블록 신설.
  원본 사진 vs 생성된 시트를 나란히 보여주고 "다시 만들기"/"이대로 진행" 버튼.
  폴링(`tick()`)이 `awaiting_sheet_approval` 상태를 받으면 이 블록을 띄우고,
  재생성 시 이미지가 캐시되지 않도록 진입할 때마다 쿼리스트링 캐시버스터를 붙인다.

## P0-6. 핵심 액션 비트가 컷에서 통째로 빠짐

**주의**: 원 계획서는 "w6.txt(에피소드 플랜)"라고 적었지만 실제로 에피소드

- `story-harness/prompts/w5.txt` — 출력 스키마에 `beats`(3~6개, 결과가 아니라

- `story-harness/prompts/w7.txt` — "이 화가 반드시 보여줘야 하는 행동 — beats"
  섹션 신설: beats의 각 행동이 최소 한 컷의 description/대사에서 드러나야 한다고

- `story-harness/webtoon.py` — `gate_beat_coverage(cuts, beats)` 신설(하드 게이트,
  실패하면 W7 재시도로 이어짐). beat 문장의 **마지막 토큰**(대개 동사)만 보고,
  조사·흔한 활용형 어미(-한다/-했다/-할게 등)를 떼어 어간만 컷의 description·
  대사 텍스트와 부분일치로 대조한다 (앞쪽 명사만으로 통과시키면 "결과 컷"에도
  그 명사가 나와서 정작 "과정이 빠졌다"는 못 잡는다 — 실제로 이 함정에 걸려서
  한 번 로직을 고쳤다). `gate_cuts()` 안에서 `episode.get("beats")`로 호출.
  `beats` 필드가 없는(과거 run) `episode`는 빈 배열로 취급해 항상 통과 —
  과거 run을 다시 돌려도 동작 불변.

## 장르 라우팅 감사 (P0 6건 외 추가 작업)

`resolve_genre_templates()`는 `_preset_map`의 **영문** 키(hunter/idol/academy)를
`genre_key`가 채워졌을 때만 본다. `genre_key`는 SEED 단계가 장르를 대신 정해줄
때만 채워지는데, 사용자가 `landing/web/index.html`의 장르 입력란(자유 텍스트
datalist)에 뭔가 직접 입력하면 그 문자열이 SEED를 안 거치고 바로
`resolve_genre_templates()`로 간다. 그 경로에서는 정확매치/부분일치만 되므로,
UI가 제안하는 한글 옵션들이 실제로는 다음과 같이 막혀 있었다(로판과 같은
버그 계열):

| datalist 옵션 | 수정 전 | 수정 후 |
|---|---|---|
| 로맨스 판타지 | 로맨스+판타지 부분일치(로판 트로프 없음) | 전용 템플릿 (P0-4) |
| 헌터·게이트 | **빈 템플릿** | 판타지+액션+스릴러 |
| 아이돌 | **빈 템플릿** | 일상+로맨스 |
| 마법학교 | **빈 템플릿** | 판타지+일상 |
| 오컬트 미스터리 | **빈 템플릿** | 판타지+스릴러 |
| 좀비 아포칼립스 | **빈 템플릿** | 액션+스릴러 |
| 무협 | **템플릿 자체가 없었음** | 전용 템플릿 신설 (사문·무공 체계 트로프) |
| 현대 판타지 | 판타지 (부분일치로 원래 됐음) | 그대로 |

`_preset_map`에 위 한글 별칭들을 추가하고, "무협"은 로판과 마찬가지로 다른
장르 조합으로는 커버 안 되는 고유 트로프(무공 체계, 사문·문파, 은원 관계)가
있어서 전용 항목으로 새로 만들었다.

## 판타지 / 일상 추가 (사용자 요청)

`genre_template.json`엔 이미 "판타지"/"일상" 키가 있어서(정확매치로 이미 동작)
백엔드 변경은 없음. `landing/web/index.html`의 장르 datalist에 두 옵션만 추가.

## 검증

- `story-harness/test_gates.py`, `webtoon-harness/test_charsheet.py` 둘 다
  이번 항목 전부에 대한 테스트를 추가하고 `ALL PASS` 확인.
- `landing`은 서버를 로컬로 띄우고(포트 8801) 브라우저(Chrome, claude-in-chrome)로
  `awaiting_sheet_approval` 상태를 시뮬레이션해 승인 화면 레이아웃을 눈으로
  확인했고, `/api/jobs/<id>/sheet-decision`에 실제 요청을 보내 라우팅이 도는
  것까지 확인했다.
- **하지 않은 것**: 사진 업로드부터 승인 클릭, 완성 웹툰까지 실제 요금이 드는
  API 호출을 태우는 진짜 end-to-end 실행은 안 해봤다 — 비용/외부 API 호출이라
  사용자 승인 없이 진행하지 않았다. 실제로 한 번 돌려서 승인 화면이 뜨는지,
  다시 만들기가 실제로 새 시트를 만드는지 확인 필요.
